### P1-1 每日刷新 cron 在全新 CI runner 上首次运行即失败（依赖 gitignored parquet，无守卫、无缓存、无生成步骤）

- 位置：`scripts/export_terminal_data.py:94`（export_picks 首个读 parquet 行）与 `:270-272`；`.github/workflows/refresh-terminal-data.yml:56-72`

- 修复成本：中

### P2-1 每日刷新的 commit 永远不会部署到终端（[skip ci] + GITHUB_TOKEN 推送双阻断）
- 描述：`commit_message: "chore(data): daily terminal refresh [skip ci]"` —— GitHub 官方 skip 关键词会让该 push 跳过所有工作流（含 Pages 部署）；且 git-auto-commit 默认用 GITHUB_TOKEN 推送，本身就不触发下游工作流。结果是「每日刷新」刷新了仓库里的 JSON，线上终端永远显示旧数据，整条管线目的落空。
- 位置：`.github/workflows/refresh-terminal-data.yml:85`（commit_message 行）
- 影响范围：终端展示层数据新鲜度——cron 的全部产出对最终用户不可见。
- 修复建议：去掉 `[skip ci]` 并用 PAT 推送或在同一工作流内串接部署步骤（配合 actor 过滤防递归）。
- 修复成本：低
- 状态：已在 3e54d901ac6fa44ca4415e5ebd2566754cdb665b 修复（drop [skip ci] so daily data commit deploys）
