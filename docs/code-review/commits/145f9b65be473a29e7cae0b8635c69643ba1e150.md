## 对照参考
- 水下图规范实现：pyfolio `plot_drawdown_underwater`（github.com/quantopian/pyfolio）与 empyrical `max_drawdown`（quantopian.github.io/empyrical）均基于收益率的累计**乘积**（起始值 1、恒正），公式 `cum/cummax − 1`；本实现把 `(cum−max)/max` 用在累计**和**（cumulative IC，可正可负、可近零）上，属类型错误（见 P2-1）。
- Streamlit 官方 caching 文档（docs.streamlit.io/develop/concepts/architecture/caching）：交互触发全脚本重跑，昂贵计算必须 `@st.cache_data`——本 app 的数据生成未用缓存（见 P3-2）。

## 问题清单
### P2-1 `_drawdown_chart` 对累计 IC（可负可近零的累加和）套用收益率水下图公式
- 描述：
  ```python
  cum_state = ic_df["ic_state"].cumsum()
  running_max_state = cum_state.cummax()
  dd_state = (cum_state - running_max_state) / running_max_state
  ```
  比例分母是「累计 IC 的历史峰值」——cumulative IC 是均值零随机变量的累加和，可负、可无限接近 0：峰值≈+0.01 而当前≈−0.02 时 dd = −300%；首个累计值为负时 running_max 为负，dd 符号直接翻转。demo 数据（mean_ic=0）下首值就有约 50% 概率为负。图表标题「Drawdown (%)」与 Max DD 标注会显示无意义数字——一个以「诚实展示不确定性」为卖点的界面上出现荒谬指标。
- 位置：`dashboard/charts_v2.py:243-246`（`_drawdown_chart`）
- 影响范围：Volatility 结构维度的 Drawdown tab 全部展示值。
- 修复建议：IC 系列改用「距峰值的绝对回撤」`cum − cummax`（不带除法）并改名（IC units, not %）；或把水下图留给 L-S 收益率序列（有 `_cumulative_ls_equity` 可复用）。
- 修复成本：低
- 状态：未修复（后续 38457c6 仅扩展 demo_data，未动 charts_v2）
