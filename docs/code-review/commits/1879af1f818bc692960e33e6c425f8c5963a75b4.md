## 问题清单
### P2-1 empyrical 未声明为依赖：核心包模块依赖可选 extra 的传递闭包
- 描述：`src/aionis/eval/tearsheet_adapter.py` 位于核心包（非 dashboard extra 门内），`import empyrical as ep` 失败即抛 ImportError；但 `pyproject.toml` 从未声明 empyrical——它仅作为 dashboard extra 里 quantstats/pyfolio-reloaded 的**传递依赖**（uv.lock 中为 `empyrical-reloaded`）进入环境。基础 `uv sync`（无 dashboard extra）安装下，任何 `import aionis.eval.tearsheet_adapter` 或收集 `tests/test_tearsheet_adapter.py` 都会失败；即使装了 dashboard extra，也是依赖「fork 的传递入口恰好提供 empyrical 导入名」这一巧合。
- 位置：`src/aionis/eval/tearsheet_adapter.py:25-30`；`pyproject.toml`（缺失项）
- 影响范围：基础安装的可导入性、CI 依赖矩阵、任何人复现 tearsheet 指标。
- 修复建议：在合适的 extra（或主依赖）显式声明 `empyrical-reloaded`（维护中的 fork，提供同名导入）。
- 修复成本：低
- 状态：未修复（main 的 pyproject.toml 仍无 empyrical 声明）

- 位置：`src/aionis/eval/tearsheet_adapter.py:33-55`
- 影响范围：未来带缺口的输入（如停跳月份）。
- 修复建议：接受带日期索引的输入并 reindex 到完整月历（缺口为 NaN 时显式报错或对齐），或文档声明「仅接受连续月份」。
- 修复成本：低
- 状态：未修复
