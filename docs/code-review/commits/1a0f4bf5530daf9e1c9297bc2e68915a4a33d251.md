## 对照参考
CFTC ~2022 合约改名（S&P 500 / Russell / Copper 的 "Market and Exchange Names" 变更）是 cftc.gov 官方公告过的事实，`cot_reports` 社区库（pypi.org/project/cot-reports）按年归档全量 zip，variant-union+按日期去重是恢复连续序列的合理做法。pandas 官方文档指出 `sort_values` 默认 quicksort **不稳定**（pandas.pydata.org/docs/reference/api/pandas.DataFrame.sort_values.html），与本 commit `drop_duplicates(keep="last")` 的组合相关（见 P3-1）。

## 问题清单
### P3-1 重叠周变体选择依赖非稳定排序，跨运行可能保留不同变体
- 描述：`sub = df[...].sort_values(DATE_C)`（默认 quicksort，非稳定）随后 `drop_duplicates(subset=[DATE_C], keep="last")` —— 同一日期存在 pre/post-2022 两个变体行时，"last" 保留谁取决于非稳定排序后的行序；注释自认「values are near-identical」，实际影响趋近于零，但严格说是非确定性行为。
- 位置：`scripts/cot_fetch.py:82,90`（该 commit 版本）
- 影响范围：改名过渡数周的 net 值取哪个变体（差异极小）。
- 修复建议：`sort_values(DATE_C, kind="stable")` 并按「优先 2022+ 变体」显式排序后再去重。
- 修复成本：低
- 状态：未修复（main 仍为默认排序）

### P3-2 部分年份 run 的新增日期 z-score 基线不完整，且单调合并使其不被后续 run 纠正
- 描述：z-score 在本 run 的 `sub` 上滚动计算（`rolling(TRAIL, min_periods=20)`）后才与 prev 合并（keep="first"）。若某 run 只成功抓到近年（如 2024+），则新增日期的 z 基于截断历史（且首 20 周为 NaN）；之后即便全量 run 补齐了更早年份，这些日期的旧 z 因 keep="first" 永不重算。
- 位置：`scripts/cot_fetch.py:92-94, 116-127`（该 commit 版本）
- 影响范围：极端抓取失败序列下 COT 展示层 z-score 有偏（自愈仅对 prev 缺失的日期生效）。
- 修复建议：合并后对每市场整段序列统一重算 net→z，再写盘（成本一次性）。
- 修复成本：低
- 状态：未修复
