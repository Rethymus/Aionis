## 问题清单
### P1-1 CN 申万分支必然崩溃：字典推导把 key 字符串当列表索引用
- 描述：`shenwan_map_original = {cn_tickers[i]: industry for i, industry in shenwan_map.items()}`——`shenwan_map` 是 `{baostock格式ticker: 行业}` 的 dict，`.items()` 解包出的 `i` 是字符串 key（如 `"sh.600000"`），而 `cn_tickers[i]` 把它当作列表下标使用，任何一次成功取数后立即 `TypeError: list indices must be integers`。正确写法应基于 `cn_tickers[i] ↔ cn_tickers_bs[i]` 的位置对应做反向映射。该路径由 `enable_cn_fetch=True`（脚本 `ENABLE_CN_FETCH=1`）触发，而全部测试均 `enable_cn_fetch=False`，缺陷零覆盖；main 至今无修复 commit。缓解因素：默认关闭、且后续 d2606d7 已把 shenwan 降为 exploratory（G3 门未过），实际跑通的是 US-only 路径。
- 位置：`src/aionis/features/regime_meso.py:276`
- 影响范围：`build_meso_regime` 的 CN 分支完全不可用；任何未来尝试启用 CN meso 的运行会崩溃（无数据损坏风险，fail loud）。
- 修复建议：`{orig: ind for orig, bs in zip(cn_tickers, cn_tickers_bs) if (ind := shenwan_map.get(bs)) is not None}`，并补一个 monkeypatch baostock 的密闭测试覆盖 enable_cn_fetch=True 路径。
- 修复成本：低
- 状态：未修复（`git log 33b5cfb..main -- src/aionis/features/regime_meso.py` 为空）

### P3-1 `_compute_sector_momentum` 逐日逐股 Python 循环，性能低下
- 描述：对每个日期执行 `stock_momentum.loc[date]` 再对每只股票 `row.get(ticker)`，约 2600 日 × 500+ 股 ≈ 百万次标量访问；用 `stock_momentum.T.groupby(sector)` 一次聚合即可向量化完成，量级提速。
- 位置：`src/aionis/features/regime_meso.py:225-250`
- 影响范围：构建脚本运行时长；不改变结果正确性。
- 修复建议：`stock_momentum.groupby(sector_map_series, axis=1).mean()` 后再 `mean(axis=1)`。
- 修复成本：低
- 状态：未修复

### P3-2 END_DATE 硬编码导致缓存层随时间静默截断
- 描述：`END_DATE = "2026-08-04"` 写死在脚本里，之后任何 rerun 都会把新数据截掉，且无"数据被截断"告警。
- 位置：`scripts/build_regime_meso.py:37`
- 影响范围：meso 层及下游 3-layer composite 的时效性。
- 修复建议：END_DATE 取 `min(today, 最新可用数据日)` 或 CLI 参数，截断时打 warning。
- 修复成本：低
- 状态：未修复
