## 问题清单
### P3-1 sig 计算逻辑复制，存在静默分歧风险
- 描述：artifacts_only 分支内联 `hashlib.sha256(json.dumps(config, sort_keys=True).encode()).hexdigest()`，与 `commit_config`（eval/phase_c.py）逐字重复；将来任何一侧改序列化（如 ensure_ascii、default 处理），两侧 sig 静默不一致。
- 位置：`scripts/phase_c_run.py:92-95`（对照 `src/aionis/eval/phase_c.py:186-189`）
- 影响范围：复跑模式的 sig 一致性
- 修复建议：在 eval.phase_c 暴露 `config_sig(config)` 供两路共用
- 修复成本：低
- 状态：未修复

### P3-2 artifacts-only 模式不校验重算 sig 与账本冻结 sig 一致
- 描述：模式自述「rebuild the SAME config (H6 -> identical sig + IC)」，但未对 ledger 已记录的 phase-C sig（a7fdb48f…）做相等断言；若缓存漂移（如 vix_cls.parquet 被重新抓取），工件会静默落到一个新 `<sig>/` 目录，成为账本外 run（dashboard 对账时会显示 ledger=None，可被发现但依赖人工看）。
- 位置：`scripts/phase_c_run.py:91-97`
- 影响范围：复跑模式的目的强度（防数据漂移被无声吸收）
- 修复建议：artifacts_only 时读 ledger 取 phase C 最新 config_committed sig，不等则 raise
- 修复成本：低
- 状态：待人工复核
