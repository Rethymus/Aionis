## 对照参考
对照 Tiingo IEX 官方字段文档（api.tiingo.com / developers.tiingo.com）：IEX 响应含 `prevClose` 字段，现算涨跌幅完全可基于昨收而非开盘，本 commit 选择 open 是对免费档限制的保守绕行。并发逐标的抓取的模式在 Cloudflare 官方文档中有明确子请求约束（免费版单次调用 50 subrequests，developers.cloudflare.com/platform/limits），本实现未设上限。

## 问题清单
### P2-1 美股 change_pct 语义为「相对开盘价」，掩盖隔夜跳空，偏离终端通用约定
- 描述：`const calcChange = last != null && open != null && open > 0 ? ((last - open) / open) * 100 : item.chp ?? null;` —— 开盘瞬间跳空缺口被归零（高开 +5% 的股票开盘时显示 ~0.00%），与所有行情终端「涨跌幅=相对昨收」的展示约定不一致；Tiingo IEX 响应本身含 `prevClose`，可用同法现算相对昨收。
- 位置：`workers/prices/src/worker.js:68-73`（该 commit 版本）
- 影响范围：picks 页美股实时涨跌列在跳空日的展示正确性（纯展示层，无研究泄漏）。
- 修复建议：优先 `(last - prevClose) / prevClose * 100`，open 仅作回退。
- 修复成本：低
- 状态：未修复（main 上仍是 from-open 逻辑）

### P2-2 CN 每标的并发 fan-out 无上限：放大上游调用 N 倍，且超过免费版 50 subrequest 上限后部分标的静默失败
- 描述：`const results = await Promise.all(parsed.map(async ({ticker, secid, code}) => { ... fetch(...) }))` —— 把一次批量请求放大为 N 次上游抓取（25 只标的=25 次），公开端点无 ticker 数量上限，>50 只时超出 Workers 免费版单调用子请求限制，被 per-ticker catch 吞掉后仅体现为 `_meta.ok` 偏小。
- 位置：`workers/prices/src/worker.js:104-135`（该 commit 版本）
- 影响范围：上游压力与配额放大；大 ticker 列表调用方拿到静默的部分结果。
- 修复建议：批量子请求（后端支持 list 查询时一次拿全量）+ 每请求 ticker 数上限。
- 修复成本：中
- 状态：已在 a4ff39e7 修复（CN 后端整体切换为 Sina `list=` 批量端点，单次子请求）

### P3-1 死代码三元 `prefix === "sh" ? 1 : prefix === "bj" ? 0 : 0`
- 描述：bj 与 sz 分支同为 `0`，`prefix === "bj" ? 0 : 0` 是无意义的死分支，说明 bj/secid 映射并未真正想清楚（北交所与深交所在东财同为 market 0，但写法应合并并注明）。
- 位置：`workers/prices/src/worker.js:101`（该 commit 版本）
- 影响范围：可读性/误导后续维护者。
- 修复建议：`const market = prefix === "sh" ? 1 : 0;` 加注释「sz/bj 同为 market 0」。
- 修复成本：低
- 状态：已在 a4ff39e7 修复（该代码路径随东财后端整体删除）
