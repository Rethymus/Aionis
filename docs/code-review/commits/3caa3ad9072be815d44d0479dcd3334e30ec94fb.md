## 问题清单
### P2-1 `pd.Timestamp.today()` 进入快照产物，破坏文档声称的"重算同一 sha256"确定性
- 描述：`snapshot_date = pd.Timestamp.today().normalize()` 被烘焙进现役成员的展开区间，parquet 内容随构建日变化；而 intake doc 复现条款写"同源数据 + 同版本包应重算得同一 sha256（H6）"——跨日 force 重建会得到不同 sha256（date_max 与行数不同），声明只在天内成立。这与"同 sig 重跑 bit-identical"的项目纪律精神相悖（虽 S0 数据快照不在 H6 冻结范围）。
- 位置：`src/aionis/ingest/csi300_constituents.py:85`（本 commit 版本）；`docs/data-intake-csi300-constituents.md:252`（复现声明）
- 影响范围：S0 universe 快照的可复现审计（跨日重建需人工解释差异来自 cap 日）。
- 修复建议：cap 改为数据驱动（如上游 CSV 的最近变更日或显式 `--as-of` 参数），或在 doc 复现条款明确"sha256 仅同日重建不变；跨日重建差异仅来自 cap 日"。
- 修复成本：低
- 状态：未修复

### P3-1 data_start 兜底在"全体 opt-in 皆 NaT"退化输入下仍会崩溃
- 描述：`data_start = opt_in_col.min()`——若某次上游数据全为 NaT opt-in，min 为 NaT，`pd.date_range(start=NaT)` 再度 raise（本次修复针对的同一崩溃形态在极端输入下复现）。真实数据仅 4/1226 NaT，风险低。
- 位置：`src/aionis/ingest/csi300_constituents.py:84`
- 影响范围：仅退化上游数据场景。
- 修复建议：`if pd.isna(data_start): return empty frame` 或 raise 带诊断的 ValueError。
- 修复成本：低
- 状态：未修复

### P3-2 上版遗留的 opt-out 闭区间边界（半开区间 PIT 语义）未在本修复中处理
- 描述：`pd.date_range(start=opt_in, end=opt_out, freq="D")` 仍含 opt_out 当天，与 intake doc 自述 `opt-in <= date < opt_out` 语义矛盾（详见 5b561e48 报告 P1-1）；本 commit 修改同一函数却未顺带修正边界，新增的 NaT 回归测试反而继续以闭区间断言（`sub["date"].max() == pd.Timestamp("2019-06-17")`）。

- 修复建议：见 5b561e48 报告；修边界时同步改 NaT 测试的 max 断言。
