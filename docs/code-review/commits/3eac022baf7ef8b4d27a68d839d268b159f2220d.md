## 对照参考
SEC 官方 Ownership XML 规范（sec.gov/info/edgar/ownershipxmltechspec-v3.pdf、ownershipformcodes.html）：`transactionCode` 中 **P=公开市场买入、S=公开市场卖出**，A=授予、M=行权、F=税扣、G=赠与；日期与金额均包在 `<value>` 子元素中（如 `transactionDate/value`）。开源对照 edgartools（edgartools.readthedocs.io，Track Insider Trading 指南）与 Apify Form 4 scraper 均按 P/S 过滤公开市场交易。本 commit 解析器恰好在这两点上与官方规范相悖（见 P1-1/P1-2），后续 9414a2ca 的修复与官方规范一致。

## 问题清单
### P1-1 transactionCode 语义错误：A/D 过滤几乎丢弃全部真实交易
- 描述：`if code not in ("A", "D"): continue  # Only pure buy (A) or sell (D)`——把 SEC `transactionCode` 当成买卖方向。官方规范中 A=授予/奖励（非自主）、D=向发行人处置；真实的公开市场买卖是 P/S。真实 AAPL 数据 110 笔非衍生交易代码为 {S:83, M:54, F:31, G:8}，本过滤器会产出 0 行（或仅留存补偿性授予）。docstring 声称 "per SEC coding" 与规范相悖。
- 位置：`src/aionis/ingest/form4.py:175-176`
- 影响范围：parse_form4_xml 全部调用方——Form 4 数据在任何真实数据上语义错误或为空。
- 修复建议：过滤 transactionCode ∈ {P, S}，并另读 acquiredOrDisposedCode 作为方向（或直接由 P/S 映射 buy/sell）。
- 修复成本：低
- 状态：已在 9414a2ca 修复（P/S 过滤 + buy_or_sell 字段，真实 AAPL 复核 83 笔卖出）

### P1-2 transactionDate 只支持 legacy year/month/day schema，新 schema 全部丢弃
- 描述：解析器只读 `date_node.find("year"/"month"/"day")`；SEC X0508+ 真实 schema 是 `transactionDate/value`（ISO 日期字符串）。真实 AAPL 申报全部使用新 schema → `year_elem is None` → 全部 continue，110 笔全被静默丢弃（返回空列表，仅一条 info 日志可察觉异常）。
- 位置：`src/aionis/ingest/form4.py:144-158`
- 影响范围：同上，解析器在真实数据上恒为空输出。
- 修复建议：优先读 `value` 子元素，legacy 作回退。
- 修复成本：低
- 状态：已在 9414a2ca 修复（双 schema + 回归测试）
