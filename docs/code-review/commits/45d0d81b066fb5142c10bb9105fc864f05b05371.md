## 对照参考
对照 Cloudflare 官方文档与社区实践（developers.cloudflare.com）：(1) `caches.default` + 显式 `cache.put(clone)`/`cache.match` 正是官方 Cache API 推荐用法，Workers 响应不会自动缓存，本实现正确；(2) 官方提供 Rate Limiting binding（developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/）与请求签名示例（signing-requests），本 Worker 的公开无鉴权代理两者皆未使用；(3) MDN URLSearchParams 官方建议对入参做校验而非直接拼接上游 URL——本实现把 `tickers` 原样插入 `api.tiingo.com/iex/${tickers}`。密钥管理（`wrangler secret put`，密钥仅存于 env）符合官方最佳实践。

- 位置：`workers/prices/src/worker.js:104-107`
- 影响范围：A股 picks/shorts 行的实时涨跌列全部显示「—」（有 24h 离场缓存掩盖部分失败）。
- 修复建议：更换为 edge 可达的 CN 行情源（Sina hq.sinajs.cn）——即后续 commit 的做法。
- 修复成本：中

### P2-1 公开无鉴权代理无输入校验、无 ticker 数量上限、无限流，Tiingo 配额可被第三方耗尽
- 描述：CORS `Access-Control-Allow-Origin: *` 且无任何鉴权；`usPrices` 将 `tickers` 查询参数原样拼进上游 URL（`fetch(\`https://api.tiingo.com/iex/${tickers}\`)`），不校验字符集/数量，任意互联网用户可用该 Worker 消耗所有者的 Tiingo 免费配额（1000 req/day）；`/api/health` 每次调用都真实打两个上游（无缓存），最易被滥用刷配额。
- 位置：`workers/prices/src/worker.js:57-59, 59-60, 144-160`（health 无缓存）
- 影响范围：Tiingo API 配额耗尽 → 正版终端用户美股实时价全部 502；cache key 未规范化（大小写/顺序不同即 miss）放大上游调用。
- 修复建议：tickers 用正则白名单（`^[A-Z.0-9]{1,10}(,...)*$`）+ 每请求上限（如 ≤50）；接入 Cloudflare 官方 Rate Limiting binding 或按 CF-Connecting-IP 计数限流；/api/health 结果缓存 60s；CORS 收敛为终端域名。
- 修复成本：中
- 状态：未修复（main 上 worker.js 仍无任何校验/限流）

### P2-2 CN 离场 24h TTL 会把上一交易日收盘价带入次日早盘（最长约 5.5 小时陈旧数据）
- 描述：`const ttl = isCnMarketOpen() ? 30 : 86400;` —— 在收盘前后（如 06:59 UTC）写入的缓存将服务到次日同一时刻；A股次日 01:30 UTC 开盘后，`cache.match` 命中旧缓存直接 `return hit`，访客在早盘看到的是前一日价格/涨跌幅，body 内 `as_of` 时间戳也是旧的。Cache API 的 `stale-while-revalidate` 头不会让 `cache.match` 自动再验证（那是给 CDN 层的提示）。
- 位置：`workers/prices/src/worker.js:135`（及同构的缓存命中早退 `:100-101`）
- 影响范围：展示层正确性——早盘访问 picks 页的 A 股实时涨跌列长时间显示昨日收盘涨跌，无任何「陈旧」提示。
- 修复建议：离场 TTL 设为「距下一次开盘的时间」（上限如 18h），或干脆统一短 TTL（如 300s）——CN 源切换 Sina 后调用量已可控；至少在响应体带 stale 标记供前端提示。
- 修复成本：低
- 状态：未修复（main 仍为 `isCnMarketOpen() ? 30 : 86400`；c9e8f9fe 只改了缓存 key 版本）

### P3-2 hook 不检查 r.ok，上游 502 时 status 仍为 "ok"
- 描述：`const responses = await Promise.all(fetches); const bodies = await Promise.all(responses.map((r) => r.json()));` —— Worker 返回 502 `{error:"tiingo:xxx"}` 时 `r.json()` 正常解析，`Object.assign` 后 prices 里混入 `error` 键，`setStatus("ok")`，上层无法区分「无数据」与「上游故障」。
- 位置：`web/src/lib/live-prices.ts:84-92`
- 影响范围：当前唯一消费方 picks-view 只取 prices（显示「—」），实际伤害小；但 status 语义错误会误导未来调用方。
- 修复建议：`if (!r.ok) throw ...` 或按响应体含 `error` 键判失败。
- 修复成本：低
- 状态：未修复

### P3-3 prewarm cron 未考虑美东冬令时；且 5 分钟 TTL 使预热在开盘即过期
- 描述：`crons = ["25 13 * * 1-5"]` 注释称 13:25 UTC = 9:25 ET——仅在夏令时（EDT=UTC-4）成立，冬令时（EST=UTC-5）实际是 8:25 ET 预热；且预热写入的缓存 TTL=300s，9:25 预热、9:30 开盘时已过期，预热收益趋近于零。
- 位置：`workers/prices/wrangler.toml:9` + `workers/prices/src/worker.js:35-38, 192-198`
- 影响范围：仅首访延迟优化失效，无功能影响。
- 修复建议：删除 cron 或改为开盘时刻预热 + 缩短为开盘后首个请求自然回源。
- 修复成本：低
- 状态：未修复
