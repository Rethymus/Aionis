## 对照参考
与 SEC 官方约定逐项核对（[sec.gov Developer Resources](https://www.sec.gov/about/developer-resources)：≤10 req/s、须声明可联系的 User-Agent，超限封 IP；[EDGAR API 文档](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)：submissions 仅含最近 ~1000 件，更早记录在 `filings.files[]` 分片）。本实现的 files[] 分页 + 块日期范围剪枝（`_block_in_range`）是正确且省请求的做法，优于 [sec-edgar-api](https://sec-edgar-api.readthedocs.io/) 库的简单全量拉取；0.15s 间隔 ≈6.7 req/s 在 SEC 官方 10 req/s 内但无裕量（该项目 3 天后在 e8545d4 统一收紧为 host 级 ≥2s）。出处域名：sec.gov、sec-edgar-api.readthedocs.io。

## 问题清单
### P2-1 永久性 4xx（如无效 CIK 的 404）也做 4 次退避重试
- 描述：`_get_json` 的 `except Exception` 把 `raise_for_status()` 抛出的 4xx 也当作瞬时错误，按 4s/8s/12s 重试 4 次后才 RuntimeError——每个坏 CIK 白等 ~24s，批量跑 587 个 issuer 时显著拖慢且无意义。
- 位置：`src/aionis/ingest/stakes_13d.py:48-65`
- 影响范围：`fetch_submissions`/`filings_13d` 的所有调用方（批量 fetch 脚本最明显）。
- 修复建议：区分 4xx（除 429）fail-fast 与 5xx/网络错误重试。
- 修复成本：低
- 状态：已在 616253e65efbfcfe162bfc3bc4220f791528db13 修复

### P2-2 0.15s 请求间隔低于项目后定的 ≥2s 礼貌红线
- 描述：`time.sleep(0.15)  # SEC fair-access: <=10 req/s`——按当时 G7 rubric（`docs/data-intake-rubric.md:95` 以 fundamentals 的 0.15s 为 binding 范例）这是合规的，且在 SEC 官方 10 req/s 之内；但 ~6.7 req/s 无安全裕量，且项目后来（AUD-05A）将 SEC 统一收紧为 host 级 ≥2s 间隔。
- 位置：`src/aionis/ingest/stakes_13d.py:59`
- 影响范围：批量拉取时对 data.sec.gov 的请求压力；封禁风险低（符合官方限速）。
- 修复建议：统一走 ≥2s 间隔的 HTTP 策略层。
- 修复成本：低
- 状态：已在 e8545d40a34b6cf73444d4621926c17ac6d707857 修复（http_policy `_policy_get` 接管）

### P3-1 User-Agent 联系邮箱为占位符
- 描述：`_UA = "Aionis research 13D-ingest contact@example.com"`——SEC 要求 UA 含真实可联系邮箱（`Sample Company Name AdminContact@sample.com` 格式）；占位邮箱不满足该要求的本意。
- 位置：`src/aionis/ingest/stakes_13d.py:28`
- 影响范围：所有对该模块请求的识别与可联系性（若被限流，SEC 无法联系到方）。
- 修复建议：改为维护者真实邮箱（全仓 4 处 `_UA` 统一）。
- 修复成本：低
- 状态：未修复（main 上仍是 contact@example.com）

### P3-2 缓存写入非原子
- 描述：`fp.write_text(json.dumps(data))` 直接写目标文件——进程在写入中途被杀会留下截断 JSON，之后每次缓存命中路径 `json.loads` 都抛 JSONDecodeError，需手工删缓存才能恢复。
- 位置：`src/aionis/ingest/stakes_13d.py:57`
- 影响范围：长跑批量 fetch 的断点续跑可靠性。
- 修复建议：写临时文件 + `os.replace` 原子改名。
- 修复成本：低
- 状态：未修复

### P3-3 archive 块拉取失败被静默跳过（仅 log.warning）
- 描述：`except Exception ... continue`——某块持续失败会使该 issuer 的 13D 历史被静默截断（事件指示特征系统性少计），决策理由（不让单块中断整个 issuer）合理但缺一个"块缺失计数"上抛汇总。
- 位置：`src/aionis/ingest/stakes_13d.py:151-155`
- 影响范围：13D 事件流的完备性（数据完整性问题，非泄漏——少计事件只会稀释信号）。
- 修复建议：在返回结构或日志中累计 skipped blocks 计数，批量脚本结束时汇总告警。
- 修复成本：低
- 状态：未修复
