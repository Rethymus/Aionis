## 对照参考
LightGBM 官方文档（lightgbm.readthedocs.io）：lambdarank 的 `group` 要求同一 query 的行连续且按 query 排序——本实现先 `np.argsort(..., kind="stable")` 排序再 `get_group_sizes`，符合官方约定；官方 + GitHub issue #5053 指出 LambdaRank 每 query 梯度复杂度 O(n²)，超大 query 组（全月日线 ~11886 行）会拖垮训练，正是后续 1376c75 修复的问题。`lambdarank_truncation_level`/`eval_at` 未设置（用默认全列表 NDCG），对 ~500 只股票的 query 可接受。

## 问题清单
### P1-1 DM 检验损失定义错误：对 lambdarank 分数取符号无意义
- 描述：`model_loss = (np.sign(oos_panel["score"]) != np.sign(oos_panel[y_col]))`，以排序分数的**正负号**与前瞻收益正负号做 0/1 损失。lambdarank 分数是任意尺度的排序量（可全为正），符号不承载方向预测语义；模块 docstring 与注释声称 "DM object is portfolio return loss differential, NOT rank-IC"，代码实际是逐股 sign-mismatch，注释与实现互相矛盾（注释块中 "Portfolio return loss (squared return prediction error)" 三行是陈旧残留）。
- 位置：`src/aionis/eval/track_b_baseline.py:355-375`
- 影响范围：`TrackBBaselineResult.dm_stat/dm_p`（pre-reg §9 检验量）在此版本完全不可解释；若以该版本跑真实数据会产出无效 DM 结论（本 commit 声明仅合成测试、未跑真实数据，实际风险未兑现）。
- 修复建议：改为 top-quantile 组合月度收益损失 vs 等权组合月度收益损失。
- 修复成本：中
- 状态：已在 d620e996 修复
