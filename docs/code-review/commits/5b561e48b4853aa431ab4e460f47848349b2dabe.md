## 对照参考
逐日展开 + 精确日期查询是 PIT 成员资格的最保守表达（对照 Algoseek Index Components 的标准 PIT 语义："removed constituents are present for the dates they were members, additions do not appear before inclusion"——即剔除日当天**不应**再算成员，半开区间 [opt-in, opt_out)，与本 repo intake 文档自述一致而与实现相反，见 P1-1）。上游包 `index-constitution`（libraries.io/pypi，MIT）提供原生 `constituents_at`；直接复用其查询而非自建逐日展开可避免边界语义漂移。来源域名：libraries.io、algoseek.com、pypi.org。

## 问题清单
### P1-1 opt-out 边界实现为闭区间，与自身文档/注释的半开区间 PIT 语义矛盾（剔除日当天仍算成员）
- 描述：intake 文档明确 PIT 语义为 `opt-in <= date < opt_out`（"constituents_at 返回 opt-in <= date < opt_out 的集合，无前视泄漏"），代码注释也写 "daily rows from opt-in to opt_out (exclusive)"，但实现是 `dates = pd.date_range(start=opt_in, end=opt_out, freq="D")`——**含 opt_out 当天**，且测试 `test_parse_opt_in_opt_out_with_exit_date` 用 `days + 1` 把闭区间固化为"预期行为"。剔除生效日（含退市触发的任意日期剔除）当天，已移除股票仍被 `constituents_on` 返回为成员。
- 位置：`src/aionis/ingest/csi300_constituents.py:104`（`pd.date_range(start=opt_in, end=opt_out, freq="D")`）
- 影响范围：Track C S0 A 股 universe 的 PIT 成员资格正确性。常规半年度调仓生效日在月中（对月末采样无影响），但退市/临时剔除的 opt-out 可落在任意日期——若恰为采样日会产生 1 只股票的横截面污染。属"违反 → P1 起步"的 PIT 成员资格红线范畴。
- 修复建议：改为 `end=opt_out - pd.Timedelta(days=1)` 或 `pd.date_range(..., inclusive="left")` 的半开区间；同步修正测试的 `+1` 断言；并到上游 `constituents_at` 对拍 2-3 个已知调仓日确认语义。
- 修复成本：低
- 状态：未修复（main 版本仍为闭区间；上游语义方向待人工复核，但"代码 ≠ 自身文档/注释"是确定的）

### P2-1 逐日展开用双层 Python 循环，全量物化 ~2.3M 行（修 cap 前 ~12M）
- 描述：`for ... in zip(...): for date in dates: rows.append((date, symbol))`——1226 段成员期 × 逐日展开纯 Python 循环；本 commit 版本还会把 300 只现役成员展开到 2099-12-31（~12M 行、数十倍内存浪费），虽被 3caa3ad9 cap 到快照日，但循环结构与逐日物化未变（区间表示 + merge_asof 可完全避免）。
- 位置：`src/aionis/ingest/csi300_constituents.py:96-106`
- 影响范围：一次性构建耗时（秒级→分钟级）与缓存体积（0.52MB parquet 本可 <50KB）；正确性无影响。
- 修复建议：保留区间表 [ticker, opt_in, opt_out]，`constituents_on` 用 `(opt_in <= t) & (t < opt_out)` 向量化筛选；或至少用 `pd.DataFrame(itertools.product(...))` 批量构造。
- 修复成本：中
- 状态：部分修复（2099→快照日 cap 已在 3caa3ad9072be815d44d0479dcd3334e30ec94fb 完成；循环物化结构未改）

### P3-1 文档声称 "G4 snapshot+sha256 pinning" 但代码未计算/记录任何 sha256
- 描述：intake 文档 G4 行写 "首次获取即落 data/cache/ + sha256 pinning"，模块只写 parquet + log 行数/日期，不产出任何摘要；实际 sha256 是 3caa3ad9 拉取后**手工**记入 intake 文档的。
- 位置：`src/aionis/ingest/csi300_constituents.py:187-203`（to_parquet 后无 hash 计算）
- 影响范围：G4 再现性纪律靠人肉兜底，程序化 rerun 无法自动校验缓存未被换。
- 修复建议：`fetch_csi300_constituents` 落盘后计算 sha256 并写入 sidecar `.sha256` 文件 + log。
- 修复成本：低
- 状态：已在 3caa3ad9072be815d44d0479dcd3334e30ec94fb 以手工记录方式缓解（自动计算仍未实现）
