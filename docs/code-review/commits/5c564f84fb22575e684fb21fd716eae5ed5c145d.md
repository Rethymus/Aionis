## 对照参考
对照增量 ETL 检查点共识（[Astronomer Airflow DAG best practices](https://astronomer.io/docs/learn/dag-best-practices)：任务幂等使 at-least-once 重试安全；[dbt 增量模型幂等性](https://techblog.finatext.com/dbt-incremental-strategy-and-idempotency-877993f48448)：在写入完全成功前推进 high-watermark 导致数据丢失；[Apache Flink checkpointing](https://nightlies.apache.org/flink/flink-docs-stable/docs/dev/datastream/fault-tolerance/checkpointing/)：at-least-once + 幂等 sink 是标准组合）。本实现的累计 parquet 全行去重正是幂等 sink（重放安全），但部分失败后仍推进窗口下界等于 at-most-once 丢事件（P2-1）；snapshot-on-arrival + sha256 封印与 reddit_sentiment 既有纪律一致。

## 问题清单
### P2-1 per-CIK 失败静默跳过 + 窗口下界推进 → 前向序列永久空洞且不可审计
- 描述：`except Exception as e: log.warning("forward_13d_cik_skip", ...); continue`（stakes_13d_forward.py:123-125；earnings_8k_forward.py:160-162 同型）。失败的 CIK 不贡献任何行，但 snapshot 仍被密封入账，账本行 `n_tickers=len(ciks)` 把失败者也计入、无 `n_failed`/失败清单字段。后续调用方按文档（5ffdbe1 后的说明）以本次 snapshot_ts 为下次 last_poll_ts → 该 CIK 在本窗口的 filings 落到下界之外，从累计序列中永久消失；仅有一条运行时 warning，账本层面不可审计。
- 位置：`src/aionis/ingest/forward/stakes_13d_forward.py:123-125`、`src/aionis/ingest/forward/earnings_8k_forward.py:160-162`、`_common.py:186-199`（append_data_ingest_ledger 无失败字段）
- 影响范围：E3 前向 I_t 完整性（13D/8-K 事件流缺事件 → 传播特征漏值）；月度冻结自动化。
- 修复建议：账本行记录 `n_failed_ciks`/`failed_ciks`（使空洞可审计）；或对失败 CIK 做有限重试；或约定"部分失败时不推进 last_poll_ts"（at-least-once + 幂等去重已天然支持重放）。
- 修复成本：低
- 状态：未修复（至 main `_common.py` 无任何失败记录字段）

### P3-1 模块 docstring「never reconstructs history」与 first-run（last_poll_ts=None）实际行为矛盾
- 描述：stakes_13d_forward.py:7-9 声称 "never reconstructs history; the first run starts the series at its own snapshot_ts"，但 `_slice_13d_forward` 在 `last_poll_ts=None` 时 `last_dt=None` → 无下界，recent 块（约最近 1000 条，可回溯数年）全部历史 filings 均被收入。行为本身无 PIT 泄漏（event_ts≤snapshot_ts 恒真），且后来被明确接纳为首跑播种语义，但本 commit 的文档与代码矛盾会误导调用方。
- 位置：`src/aionis/ingest/forward/stakes_13d_forward.py:7-9`（docstring）；`_slice_13d_forward` :57-58（`last_dt=None` 无下界）
- 影响范围：调用方对首跑数据范围的理解；8-K/宏观收集器同型。
- 修复建议：已由后续文档解决——明确 first-run None = 开下界全量收集。
- 修复成本：低
- 状态：已在 5ffdbe1c6b95c07f55cb5736d83c7d427902c017 修复（docstring 澄清 first-run 播种语义，无行为变更）

### P3-2 `_common.to_utc_dt` 的 "Z" 后缀在 Python 3.10 抛 ValueError
- 描述：与 Slice 1 `forward_ledger._to_utc_dt` 同型：`datetime.fromisoformat` 3.11 前不支持 `Z`；`requires-python>=3.10` 下以 Z 形式传入 snapshot_ts/last_poll_ts 会 fail-fast 报错（无静默错误，uv.lock 实际运行时大概率 ≥3.11）。
- 位置：`src/aionis/ingest/forward/_common.py:64-70`
- 影响范围：仅 Python 3.10 解释器下的可用性。
- 修复建议：入口处 `z.replace("Z", "+00:00")` 归一。
- 修复成本：低
- 状态：未修复（待人工复核：实际 CI 解释器版本）
