## 对照参考
pydantic v2 官方文档（docs.pydantic.dev）推荐 `field_validator` 单字段、`model_validator(mode="before"/"after")` 跨字段、`ConfigDict(extra="forbid")` 拒绝未知字段——本实现三者用法均与官方一致；`json.dumps(sort_keys=True)` 确定性序列化亦是标准做法。进程内去重注册表对照 openregistry/entry-points 类设计可知其仅是会话级索引，持久去重需落盘（本仓库 README 已把 `evals/trials/*.json` 定为持久 registry，但代码未闭环，见 P2-1）。

## 问题清单
### P2-1 trial-id 去重注册表仅进程内、不校验磁盘持久 manifest
- 描述：`_trial_id_registry: set[str] = set()` 是模块级内存集合，`register_trial_id()` 只查内存：
  ```python
  if trial_id in _trial_id_registry:
      raise ValueError(...)
  _trial_id_registry.add(trial_id)
  ```
  README 声明持久 registry 为 `evals/trials/{trial_id}.json`（git-tracked），但注册时不检查该目录是否已存在同 id 文件。进程重启或跨进程（如 CI 与本地）注册同一 trial id 不会报错，README「Duplicate trial IDs are rejected」的承诺仅在同进程内成立。RD-17 的目的是防 silent trial expansion（防 p-hacking），去重保证存在跨会话缺口。
- 位置：`src/aionis/reporting/trial_intent.py:474-491`
- 影响范围：所有依赖 `register_trial_id()` 防重的调用方；治理审计中同 id manifest 可能被覆盖/并存。
- 修复建议：`register_trial_id(trial_id, registry_dir=None)` 增加可选目录参数，注册前 `os.path.exists(registry_dir / f"{trial_id}.json")` 检查；或提供 `load_registry_from_dir()` 在启动时重建内存集合。
- 修复成本：低
- 状态：未修复（后续 c9e9eb6 仅注册了两个真实 manifest，未改代码）

### P3-1 TrialStatus 文档字符串「Any → BLOCKED」与转移表不符
- 描述：类文档写「Any → BLOCKED (irrecoverable error or policy violation)」，但 `can_transition_to` 的 `valid_transitions` 只允许 PLANNED/APPROVED/ACTIVE → BLOCKED；终态（CLOSED/SUPERSEDED/FAILED/REJECTED）映射为空集，无法进入 BLOCKED。文档与实现不一致，README 同样转述了「Any → BLOCKED」。
- 位置：`src/aionis/reporting/trial_intent.py:104`（docstring）与 `:141-163`（转移表）
- 影响范围：仅文档误导，无行为缺陷。
- 修复建议：将 docstring/README 措辞改为「非终态 → BLOCKED」，或在转移表中显式允许终态 → BLOCKED（需产品决策）。
- 修复成本：低
- 状态：未修复

### P3-2 `from_json` 对非 dict JSON 抛裸 AttributeError
- 描述：`from_json` 中 `assert_no_outcome_fields(data)` 直接调用 `raw.keys()`；若输入是合法 JSON 但顶层数组（`json.loads` 返回 list），将抛 `AttributeError: 'list' object has no attribute 'keys'` 而非干净的 `ValidationError`。模型侧 `model_validator(mode="before")` 有 isinstance 防护，此入口没有。
- 位置：`src/aionis/reporting/trial_intent.py:438`
- 影响范围：调用 `from_json` 的解析路径，错误信息不友好。
- 修复建议：`from_json` 中先 `if not isinstance(data, dict): raise ValueError(...)` 再调用 guard。
- 修复成本：低
- 状态：未修复

### P3-3 Multiplicity 冗余校验（死代码重复）
