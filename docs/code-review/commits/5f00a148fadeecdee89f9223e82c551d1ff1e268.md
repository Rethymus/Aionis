## 对照参考
Streamlit 官方文档建议对随磁盘/外部变化的数据使用 `st.cache_data(ttl=...)` 或以文件 mtime 作为缓存键参数，避免读到陈旧数据（docs.streamlit.io）。本 commit 沿用了仓库内既有的无 TTL 模式，一致性可取但继承了陈旧性。plotly 柱图 + `add_hline` 用法与官方示例一致（plotly.com/python）。

## 问题清单
### P3-1 placebo p 值硬编码回退 "≈0.057"
- 描述：`placebo_str = _fmt_num(placebo_n1.get("p_value")) if placebo_n1 else "≈0.057"` — 当 ledger 行缺 `C_placebo` 时，UI 直接显示写死的 0.057，未来不同 run 的数据会被旧数字顶替，可能误导。
- 位置：`dashboard/app.py:452-453`
- 影响范围：仅 Strategy Return tab 的说明文字；数据面板本身不受影响。
- 修复建议：缺失时显示 "—" 并保留文字说明，不伪造数值。
- 修复成本：低
- 状态：未修复

### P3-2 `st.cache_data` 无 TTL，新 run 不刷新
- 描述：`_latest_strategy_return` 依赖的 `_ledger_rows` 均为 `@st.cache_data(show_spinner=False)` 无 TTL；ledger 是 append-only，新策略评估落地后该 tab 在同一进程内永远显示旧行，需重启或清缓存。
- 位置：`dashboard/app.py:95-106`（及既有 `dashboard/app.py:61-63`）
- 影响范围：本地分析 dashboard 的数据新鲜度；属沿袭既有模式而非本次引入。
- 修复建议：为 ledger 读取加 `ttl=60` 或以文件 mtime 作缓存键。
- 修复成本：低
- 状态：未修复
