## 对照参考
期望最大 Sharpe 公式 `(1-γ)·Φ⁻¹(1-1/N) + γ·Φ⁻¹(1-1/(N·e))` 与公开的 Bailey-LdP 实现一致（VSFS 论文代码用 `np.euler_gamma` 同式；github.com/mnemox-ai/deflated-sharpe、pypi.org/project/jsharpe 同源）。但本仓库自 init 起已有 `src/aionis/eval/multiple_testing.py` 委托 `purgedcv.deflated_sharpe_ratio_full` / `probability_of_backtest_overfitting`（purgedcv 是 pyproject 钉住的依赖）——本 commit 又手写一套，与项目 reuse-first 纪律相悖。来源：github.com、pypi.org、papers.ssrn.com（abstract_id=2460551）。

## 问题清单
### P2-1 与既有 purgedcv 委托实现重复（同包两套 DSR/PBO）
- 描述：仓库自 init（ce03644）起就有 `src/aionis/eval/multiple_testing.py`，其中 `deflated_sharpe`/PBO 均委托已钉版本的 `purgedcv`。本 commit 手写 `src/aionis/eval/deflated_sharpe.py` 再实现同一统计量（且 V[SR] 用 `sqrt(1/(n_obs-1))` 近似、CSCV 行组合而非时间分块，两处口径与 purgedcv 版可能不同）。后续 `scripts/track_adaptive_run.py` 调用的是新手写版，而 `risk_metrics.py`/策略评估用的是 purgedcv 版——同一仓库同一指标两种数值口径并存。
- 位置：`src/aionis/eval/deflated_sharpe.py:1-123`（对照 `src/aionis/eval/multiple_testing.py:165-248`）
- 影响范围：任何同时读两处 DSR/PBO 的报告/展示会出现口径不一致；维护双份。
- 修复建议：以 purgedcv 委托为单一事实源，新模块仅保留 purgedcv 没有的"仅知 max 与 n_trials"入口并在 docstring 标注两者关系；或删除重复实现。
- 修复成本：中
- 状态：未修复（HEAD 仍双实现并存）

- 位置：`src/aionis/eval/deflated_sharpe.py:60-71`
- 影响范围：所有调用方的统计解释正确性。
- 修复建议：docstring 明确输入契约（per-period Sharpe + 匹配矩），或提供年化换算参数。
- 修复成本：低
- 状态：未修复
