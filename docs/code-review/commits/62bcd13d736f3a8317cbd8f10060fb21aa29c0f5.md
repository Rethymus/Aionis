## 问题清单
### P2-1 committed-vs-revealed 计数按行数而非按月，revealed 双臂计数导致 pending 为负
- 描述：`commit_forward_prediction` 每月写 1 条 `forward_prediction_committed` 行，而 `reveal_forward_outcome` **按臂**写行（arm_base/arm_e13 各一条 → 每月 2 条 `forward_outcome_scored`）。`_committed_vs_revealed` 直接 `pending = committed - revealed`：首月揭示后 committed=1、revealed=2、pending=-1，界面 "Pending" 指标显示负数。测试用 3 commit + 2 scored 的 1:1 假数据掩盖了该语义差。
- 位置：`dashboard/app.py:176-183`（`_committed_vs_revealed`）
- 影响范围：Forward IC tab 的监控指标可信度（运维会看到 pending=-1）。
- 修复建议：revealed 按 `(predict_ts, target_t)` 去重后计数，或 `revealed = len(distinct predict_ts)`。
- 修复成本：低
- 状态：未修复（main 上 `dashboard/views/forward.py:117` 原样保留 `committed - revealed`）

### P2-2 parity 进度条缩放数学误导（30 个月即满格）
- 描述：`prog_frac = min(parity["frac_lo"] * 2, 1.0)` = min(n_months/30, 1)——进度条在 30 个月就到 100%，而下方 caption 与语义是 "Progress to 60 months"。注释 "(0 to 2x the lower gate)" 说明是有意放大，但与紧邻的 `frac_lo` 百分比文案自相矛盾，用户会把半程看成全程。
- 位置：`dashboard/app.py:884-886`
- 影响范围：Forward IC tab 展示层。
- 修复建议：`st.progress(min(parity["frac_lo"], 1.0))` 或在 caption 明示缩放。
- 修复成本：低
- 状态：未修复

### P3-1 view_forward_ic 独立调用时 config_sha256 回退 "unknown"；_forward_kpi 字段名 t_hac 实为 DM stat
- 描述：`forward_run.get("config", {}).get("config_sha256", "unknown")` —— 保存的 config dict（build_forward_config 产物或 runner 的 `{}`）并不含 `config_sha256` 键，独立调用时 committed-vs-revealed 恒为 0/0/0（main() 里靠目录名回退侥幸正确）；另 `_forward_kpi` 把 `dm_stat` 映射到键名 `t_hac`，命名误导。
- 位置：`dashboard/app.py:846-848、148-156`
- 影响范围：helper 复用方、KPI 键消费者。
- 修复建议：签名上直接依赖传入的 config_sig；键名改 `dm_stat`。
- 修复成本：低
- 状态：未修复
