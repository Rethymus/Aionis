## 问题清单
### P2-1 live runner 未把 membership 传入 fit 路径，I4 no-forward-fill 断言在真实运行中失效
- 描述：`forward_commit.fit_forward_single` 文档声称 "the live runner passes the real membership"（belt-and-suspenders PIT 成分股断言），但 `forward_commit_runner.main()` 调用 `run_forward_commit(...)` 时未传 `membership=mem`，断言在 live 路径为 dead code。
- 位置：`src/aionis/eval/forward_commit_runner.py:280-286`
- 影响范围：E3 前瞻 commit 的测试截面成分股与 PIT 成分股失配时只能靠上游 `_clean_panel` 一层防御，不会硬报错。
- 修复建议：main() 中将 `membership=mem` 传入 `run_forward_commit`。
- 修复成本：低
- 状态：已在 7e666d8 修复（AUD-06 readiness gate：live Slice 6/7 调用方强制 "membership passed to fit + test tickers == constituents_on(t)"，opt-in）

### P2-2 冻结 config 未记录 LLM 客户端 model 名与采样参数（I8 完整性缺口）
- 描述：`build_forward_config` 只记录 `"provider": "glm"`；而 `_build_llm_client` 使用 `provider.model`（默认 "glm-4-flash"）且 `GLMCausalEdgeClient` 固定 `temperature=0.1`。同一 provider 名下换 model 或改温度不会翻转 `config_sha256`，属 I8（静默变异向量）不完整。
- 位置：`src/aionis/eval/forward_commit_runner.py:262-277`、`src/aionis/features/causal_broadcast.py:139-142`
- 影响范围：arm_e13 事件通道的 LLM 边在配置层面不可完整审计（磁盘缓存键为 text 哈希，也不含 model 名）。
- 修复建议：把 `provider.model`、`temperature` 与客户端类版本写入 config dict。
- 修复成本：低
- 状态：待人工复核（后续 AUD-06 gate 引入 provider_cutoff_policy，但 model 名是否入 config 未确认）

### P2-3 predict_date 取 panel 最大日期，与 ledger 记录的月末日 predict_ts 可能错位
- 描述：`run_forward_commit` 中 `predict_date = panel_base["date"].max()`（来自价格缓存），而 `predict_ts` 由 `_nyse_month_end_session(today)` 计算；价格缓存过期时 commit 会把陈旧截面的分数密封在月末时点名下，时点语义错位且无校验。
- 位置：`src/aionis/eval/forward_commit.py:288`
- 影响范围：E3 前瞻账本的时点可信度（I1）。
- 修复建议：断言 `predict_date == predict_session`，失配即拒绝。
- 修复成本：低
- 状态：已在 7e666d8 修复（AUD-06 fail-closed：price coverage + "commit targets the requested live session" 校验，live 路径 opt-in）

### P3-1 跨模块访问 forward_ledger 私有成员

- 修复成本：低
