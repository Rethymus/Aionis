## 对照参考
对照 arch 包（bashtage/arch，本项目依赖 `arch>=8.0` 已在白名单）的 `CircularBlockBootstrap` / `MovingBlockBootstrap`：arch 明确区分「end-to-start wrap around」（循环）与「尾部截断」（moving）两种实现，且 `MovingBlockBootstrap` 通过覆写索引生成逻辑实现截断。本脚本的实现是"允许任意起点 + 尾部截断"，既非标准 circular 也非标准 moving（MBB 只允许起点 0..n-block）。出处：arch.readthedocs.io（Time-series Bootstraps 页）、github.com/bashtage/arch。

## 问题清单
### P2-1 「循环块 bootstrap」实为尾部截断采样，样本量可静默小于 n_target
- 描述：`sample = np.concatenate([ic[s : s + BLOCK_MONTHS] for s in start_idxs])[:n_target]`，`start_idxs` 取值 `[0, n_pop)`。当 `s + 12 > n_pop`（n_pop=71 时 s≥60 概率约 15.5%）该块被截短，既无 wrap-around 也不限制起点。后果：(a) 与 docstring「circular block bootstrap」不符（属 moving/truncated 变体）；(b) 期望块长约 11.1 而非 12，n_target=120 时期望样本仅约 111 个观测，且极端情况下拼接总长 < n_target 时 `[:n_target]` 静默返回更短的样本，`mean`/`_nw_se` 在低于目标的样本量上计算；(c) 序列头 11 个观测的入样概率低于其余观测（起点约束 s∈[max(0,i-11), i]）。偏差方向偏保守（n 偏小 → SE 偏大 → 更难宣告等效），与「结构性功效不足」结论同向，不翻转结论，但数字（如 bootstrap P(equivalence)、RCI_half 分位数）有轻微失真。随附内部评审 `reports/audits/2026-08-05-power-analysis-review.md` 断言「circular block bootstrap 实现正确」，与代码事实不符（该评审结论过于乐观）。
- 位置：`scripts/track_c_power_analysis.py:96-99`（`_block_bootstrap_power` 内 concatenate 行）
- 影响范围：功效分析数字（写入 `runs/track_c_confirmatory_power_analysis.json` 与决策简报）精度；不影响冻结面与账本。
- 修复建议：用模运算实现真循环块（如 `idx = (np.arange(BLOCK_MONTHS)[None,:] + start_idxs[:,None]) % n_pop; sample = ic[idx].ravel()[:n_target]`），或直接复用 `arch.bootstrap.CircularBlockBootstrap`；并在采样后断言 `len(sample) == n_target`。
- 修复成本：低
- 状态：未修复（`git log <hash>..main -- scripts/track_c_power_analysis.py` 无后续改动）
