## 对照参考
对照事件溯源/WAL 的成熟实践（[microservices.io event-sourcing](https://microservices.io/patterns/data/event-sourcing.html)：保存事件应为单原子操作；[Wikipedia write-ahead logging](https://en.wikipedia.org/wiki/Write-ahead_logging)；[Cockroach Labs: idempotency and ordering](https://www.cockroachlabs.com/blog/idempotency-and-ordering-in-event-driven-systems/)）。本模块的"parquet artifact + 账本行"是典型 dual-write：业界共识要么让日志追加成为唯一原子操作、要么在恢复/重入路径用幂等键做对账。本实现有幂等键（scores_sha256）但幂等分支不读账本对账（P2-1）。commit-then-reveal 本身与承诺方案/预测注册表（OSF preregistration）的时锁披露同构，方向正确。

## 问题清单
### P2-1 双写崩溃窗口：幂等重入不核对账本行，`committed:True` 可能谎报
- 描述：`commit_forward_prediction` 先 `path.write_bytes(tmp_bytes)`（forward_ledger.py:285）后 `_append_ledger_row`（:286）。若两步之间进程崩溃/断电，parquet 已存在而账本无 commit 行。重试时幂等分支（:250-260）仅比较 parquet 字节相同即返回 `{**row, "committed": True, "_appended": False}`——**不检查账本中是否真的存在该 commit 行**。结果：API 报告"已封印"，但承诺行永久缺失；后续 reveal 会正确拒绝（no_matching_commit，fail-closed），但月度调度器会误信已提交且审计链断裂，需人工删 artifact 才能恢复。测试 `test_recommit_identical_scores_is_idempotent` 仅覆盖"行已存在"路径。
- 位置：`src/aionis/reporting/forward_ledger.py:250-260`（幂等分支缺对账）；`:285-286`（写序）
- 影响范围：E3 前向月度提交的崩溃恢复；Slice 3+ 调度器的提交状态机。
- 修复建议：幂等分支调用 `read_forward_rows` 核对该 (config_sha256, predict_ts) 的 commit 行是否存在，缺失则补写账本行（`_appended: True`）；或反转顺序为"先 append 行、后写 artifact"并在读侧容忍缺文件。
- 修复成本：低
- 状态：未修复（至 main 该文件零改动）

### P2-2 reveal 幂等静默吞掉 ic_point 漂移，H6 破坏不可见
- 描述：`reveal_forward_outcome` 幂等分支（:413-429）对已 scored 的 (config_sha256, predict_ts, arm) 直接返回 `existing["ic_point"]`，**不与本次传入的 ic_point 比较**。若重算得到不同 IC（数据修订/代码变更/H6 确定性破坏），分歧被无声吞掉——与 commit 路径对 scores 变更显式拒绝（mutation refused）不对称。对一个以"检测 rerun 漂移"为核心价值的系统，这使前向轨的 H6 破坏无法被发现。测试 `test_reveal_idempotent_no_duplicate_identical_ic` 仅传相同 ic。
- 位置：`src/aionis/reporting/forward_ledger.py:413-429`
- 影响范围：E3 前向轨 H6 确定性审计；Slice 4 计分循环。
- 修复建议：幂等分支比较 `float(ic_point) != existing["ic_point"]` 时 log.warning（或返回 `ic_mutation_detected` 拒绝），与 commit 的 I2 行为对称。
- 修复成本：低
- 状态：未修复（至 main 该文件零改动）

### P3-2 `_to_utc_dt` 对 "Z" 后缀解析在 Python 3.10 会抛 ValueError
- 描述：docstring 与参数化测试（含 `"2026-07-31T20:00:00Z"` 变体）声称 Z 形式可折叠为同一 canonical 键，但 `datetime.fromisoformat` 直到 3.11 才支持 `Z`；`pyproject.toml` 声明 `requires-python = ">=3.10"`。在 3.10 上该路径直接 ValueError（fail-fast，无静默错误，且 uv.lock 锁定的实际运行时大概率 ≥3.11）。

- 修复建议：`_to_utc_dt` 里对尾部 `Z` 做 `x.replace("Z", "+00:00")` 归一，或声明 requires-python>=3.11。
