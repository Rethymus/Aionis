## 对照参考
EDGAR Archives 的 filing `index.json`（`directory.item[]` 含 name/type/size）是 SEC 官方约定（sec.gov/Archives、edgartools 文档 edgartools.readthedocs.io 同样经由 index.json 或完整提交清单定位 primary document）；主流实现（edgartools、sec-api.io）以 `primary_doc.xml`/`document.xml` 或 submission 型别字段选择主文档，而非"第一个 .xml"。本实现的双 schema 容错合理，但主文档选择缺少类型/名称优先级（见 P2-1）。

## 问题清单
### P2-1 主文档选择取"第一个 .xml"，多 XML 申报可能静默取错
- 描述：`xml = next((n for n in names if n.lower().endswith(".xml")), None)`——Form 4 申报目录常含主文档 XML 之外的 XML（exhibit、渲染用文件等）；选中非主文档时 `parse_form4_xml` 大概率返回 0 行（仅 info 日志），该申报被静默跳过，数据悄悄缺失。无按名（primary_doc/document/ownership）或 type 字段的优先级。
- 位置：`src/aionis/ingest/form4_orchestrator.py:57`
- 影响范围：fetch_form4_transactions 的逐申报产出完整性（0 行不报警，仅 count=0 info）。
- 修复建议：优先匹配 `primary_doc.xml`/`document.xml`/含 "ownership" 的 XML；0 行解析时升级为 warning 并记 accession。
- 修复成本：低
- 状态：待人工复核（后续真实多申报运行未见相关 fix commit；缺失幅度需真实 index.json 对照）
