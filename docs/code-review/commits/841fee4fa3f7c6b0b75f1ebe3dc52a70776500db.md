## 对照参考
LightGBM 官方文档要求 lambdarank 的 query group 连续排序且 group 尺寸之和等于样本数——本实现 `np.argsort(groups, kind="stable")` + `get_group_sizes` 正是官方推荐形态（lightgbm.readthedocs.io）；`pd.concat` 未显式传 `sort=` 在 pandas 未来版本有 deprecation 语义（pandas.pydata.org whatsnew），已在后续 52a8d09 修复。出处：lightgbm.readthedocs.io、pandas.pydata.org。

## 问题清单
### P3-1 训练特征与 relevance 的重对齐依赖隐式不变量（-1 ⟺ NaN）
- 描述：`valid_mask = train_returns.notna().to_numpy()` 重新推导过滤掩码来取特征行，而 clean 序列来自 `filter_valid_ranking_samples`（掩码为 `~isna & relevance != -1`），随后用 `argsort(train_grp_clean)` 按位置对齐特征与标签。两者一致的前提是 `transform_to_relevance` 只对 NaN 收益产出 -1（当前属实：越界值被 clamp 而非 -1）。若 ranking_contract 将来引入别的 -1 来源（如退化组合单独标记），特征与标签将静默错位或 IndexError。
- 位置：`src/aionis/eval/track_c_joint.py:375-381`
- 影响范围：训练数据构造的正确性（当前正确，属脆弱耦合）。
- 修复建议：让 `filter_valid_ranking_samples` 一并返回掩码/索引，特征直接用同一掩码过滤，消除双重推导。
- 修复成本：低
- 状态：未修复（后续 c98f4c8/52a8d09 未触及该段）

### P3-2 runner 的 `PHASE_C_NO_LEDGER` 是无效开关（复制粘贴残留）
- 描述：`__main__` 里 `if os.environ.get("PHASE_C_NO_LEDGER") == "1": print(...)` 之后无条件 `main()`，而 runner 本身没有任何 ledger 写入路径——该环境变量在其他 phase runner 中用于切换行为，在这里纯属装饰，误导使用者以为有门控。
- 位置：`scripts/track_c_joint_run.py:150-153`
- 影响范围：可操作性/文档性。
- 修复建议：删除该分支或改为统一的 no-op 说明。
- 修复成本：低
- 状态：未修复（main 上仍存在）

### P3-3 `pd.concat` 未显式 `sort=`（pandas4 语义）+ 契约用裸 `assert`
- 描述：`build_joint_panel` 的 concat 依赖 pandas 当前默认列排序行为，pandas 未来版本发出 FutureWarning/行为变化；`assert embargo_sessions >= 21` 用裸 assert 表达契约（`python -O` 下会被剥离）。
- 位置：`src/aionis/eval/track_c_joint.py:217`、`:313`
- 影响范围：未来 pandas 升级的可复现性；优化模式下的契约检查失效。
- 修复建议：concat 显式 `sort=False`；契约检查改 `raise ValueError`。
- 修复成本：低
- 状态：已在 52a8d0982de07fda7fffbcef9fdec5db73328740 修复（concat sort= 部分）
