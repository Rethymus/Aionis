## 对照参考
SEC EDGAR EFTS full-text search API 的响应中每个 hit 含 `_source.display_names`（实体名数组）、`file_date`、`adsh`（accession number）（sec.gov / dev.to 逆向文档、browserless.io 技能文档）。本项目按 display_names[0]=issuer、[1]=filer 的约定解析与该 API 的实体顺序一致，且 commit message 用"自然人不能是 issuer"的语义证据自证纠正——方法论可取；但 EFTS 官方响应含 `adsh` 唯一键，本项目聚合未用它去重（见 P2-1）。

## 问题清单
### P2-1 聚合无 accession 去重，联合申报可能重复计数
- 描述：`for f in glob.glob("data/cache/efts_13d_*.json")` 逐 filer 缓存文件聚合时，仅以 `display_names`/`file_date` 生成行，未使用 EFTS 响应自带的 `adsh`（accession）去重；同一份 13D（多 reporting person 联合申报、或同一文档被多个 filer 查询命中）会在不同缓存文件中重复出现，`total_filings`（2872）与 active_filers 计数可能被抬高。
- 位置：`scripts/export_terminal_data.py:141-160`（export_smart_money 循环体）
- 影响范围：仅展示层 KPI（total_filings/n_filers/active_filers 计数），无研究影响。
- 修复建议：以 (adsh 或 filer+target+date) 为键 set 去重后再计数。
- 修复成本：低
- 状态：待人工复核（后续 dd0ba70 改用 daily crawler index 补充，但主版本至今未见去重键；重复幅度需与 EDGAR 原始 accession 对照确认）

### P2-2 空数据路径未处理，隐式 JSON 类型可致 never[] 构建失败
- 描述：`rows` 为空时输出 `active_filers: []`、`recent_filings: []`；前端 `smartMoney as typeof smartMoney` 的类型直接取自提交时 JSON 字面量，一旦导出产生空数组，TypeScript 推断为 `never[]`，`.map` 回调参数类型崩塌、部署构建失败。该隐患在 dd0ba70 引入 daily-index 空行为后真实发生。
- 位置：`web/src/data/aionis/index.ts:43`（`smartMoney: smartMoney as typeof smartMoney`）；`scripts/export_terminal_data.py:170-175`
- 影响范围：CI/部署构建（batch_20 的 ac35c4d 即为此打的补丁）。
- 修复建议：为 smartMoney 声明显式 TS interface，而非 `typeof json`。
- 修复成本：低
- 状态：已在 ac35c4d 修复（显式 SmartMoney 类型 + never[] 防御）

### P3-1 active_filers 仅统计最近 300 行的隐式窗口
- 描述：`active = Counter(r["filer"] for r in rows[:300]).most_common(10)`——"最活跃 filer"实际是"最近 300 份申报中的最活跃"，窗口语义未在 UI 方法论中披露；后续 daily-index 行无 filer 时该窗口直接产出空榜。
- 位置：`scripts/export_terminal_data.py:166`
- 影响范围：展示层排名语义；后续版本曾因此出现空榜。
- 修复建议：窗口写进 methodology 字符串或改全量统计。
- 修复成本：低
- 状态：已在 ca93f39 修复（改为全 real-filer 行统计并披露）

### P3-2 损坏缓存文件被静默跳过
- 描述：`except (json.JSONDecodeError, KeyError): continue` 整文件静默丢弃，无日志；缓存腐烂时计数悄然缩水，不可观测。
- 位置：`scripts/export_terminal_data.py:159`
- 影响范围：导出数据完整性观测性。
- 修复建议：except 分支打印文件名与异常摘要。
- 修复成本：低
- 状态：未修复
