## 对照参考
回放测试的成熟范式是 vcr.py / pytest-recording（vcrpy.readthedocs.io、github.com/kiwicom/pytest-recording）：录制一次、离线重放、CI 锁 `--record-mode=none` + `--block-network`。本实现是"手工 cassette"路线（手写合成 fixture + 直接回放 content），符合离线确定性原则且不引入依赖；对 parser 版本的锚定，成熟做法是用模块版本号或 git commit，而非 `inspect.getsource` 单函数哈希（见 P2-1）。

## 问题清单
### P2-1 parser_version_sha256 只哈希 `_parse_and_validate` 单函数源码，稳定性归因不完整
- 描述：
  ```python
  source = inspect.getsource(_parse_and_validate)
  return hashlib.sha256(source.encode("utf-8")).hexdigest()
  ```
  解析 verdict 实际还依赖 `ERL` pydantic 模型、`ActionType/ActorType/ObjectType/TemporalClass` 枚举定义、`text_hash` 等 schema.erl/llm_client 内容。这些任一变化（例如枚举新增取值使原 UNKNOWN_ENUM fixture 变 VALID）都会改变回放 verdict，但 `parser_version_sha256` 不变——RD-11 的目的是用「parser 版本未变 → verdict 应稳定」做回归归因，哈希覆盖不全会导致漂移误归因为"稳定性问题"或漏报 parser 变更。
- 位置：`src/aionis/extraction/replay.py:52-57`
- 影响范围：所有用 `parser_version_sha256` 做跨时间 verdict 稳定性比较的消费方（回归报告/审计）。
- 修复建议：同时哈希 `_parse_and_validate` 所在模块与 `aionis/schema/erl.py` 的源码（`inspect.getsource(module)` 或读 `__file__` 源字节），拼入版本摘要。
- 修复成本：低
- 状态：未修复（该文件后续无 commit）

### P3-1 跨模块 import 私有符号 `_parse_and_validate`
- 描述：`from aionis.extraction.llm_client import _parse_and_validate, text_hash` —— 下划线私有函数被另一模块直接依赖，llm_client 内部重构（改名/改签名）会在 import 时才暴露，耦合方向越界。
- 位置：`src/aionis/extraction/replay.py:22`

- 修复建议：在 llm_client 中将该函数提升为公开 API（去下划线 + docstring），或提供公开包装。
- 修复成本：低
- 状态：未修复

### P3-2 pydantic 错误消息文本耦合，v1 风格 regex 在 v2 下永不命中
- 描述：UNKNOWN_ENUM 分支用 `re.search(r"input_value='([^']+)'", str(e))` 提取非法值。项目用 pydantic v2（错误串中 `input_value=X` 不带引号），带引号 regex 永不匹配，恒走截断的 generic 分支——verdict 仍正确但 error_summary 丢失非法值信息；且依赖错误消息措辞（`"action" in error_str and "enum" in error_str`）本身就是脆弱耦合。另外 `_detect_unknown_enum_values(erl)` 在 `_parse_and_validate` 成功返回后调用属防御性死代码（枚举若非法早在 pydantic 校验时抛错）。
- 位置：`src/aionis/extraction/replay.py:231-243, 266`
- 影响范围：仅 error_summary 质量，不影响 verdict 正确性。
- 修复建议：改用 `e.errors()` 结构化列表检查 `type == "enum"` 与 `input` 值；删除成功路径后的枚举复查或注明为 belt-and-suspenders。
- 修复成本：低
- 状态：待人工复核（regex 是否命中取决于 pydantic 版本行为，需实测确认）

### P3-3 `read_text()` 未指定 encoding，跨平台哈希不稳定
- 描述：`raw_content = fixture_path.read_text()` 后 `hashlib.sha256(raw_content.encode("utf-8"))`。Windows + Python < 3.15 默认 locale 编码（中文环境 cp936）读入，再以 utf-8 编码回写哈希；若未来 fixture 含非-ASCII 字符，Windows/Linux 上 `raw_response_sha256` 不一致，违背「bit-stable replay」承诺（当前 fixture 全 ASCII，暂无实际影响）。
- 位置：`src/aionis/extraction/replay.py:150-151`
- 影响范围：跨平台回放结果的哈希可比性。
- 修复建议：`read_text(encoding="utf-8")`。
- 修复成本：低
- 状态：未修复
