## 问题清单
### P2-1 探索性 sweep 未移植 phase_d_run 的退化 bundle 守卫
- 描述：`scripts/phase_d_run.py:99-118` 在 confirmatory 侧强制 `sic coverage >= 80%` 且 `peer_mom 有有效值`，否则 `SystemExit` 拒绝写无意义的 confirmatory:first；而本 sweep 的 `_build_rel_extra`（`sensitivity_horizon.py:57-101`）只打印 `peer_mom valid=...`/`stakes_13d_event sum=...` 不做任何阈值判定。若缓存退化（如 SIC map 部分缺失 → peer_mom 全 NaN），h=10/42 的 arm_rel 与 arm_base 实际等价，"null holds" 会成为**空洞的稳健性证据**（无信号 ≠ 信号稳健为 null）。
- 位置：`scripts/sensitivity_horizon.py:99-101`（打印后无 guard）
- 影响范围：commit message 与 ledger notes 宣称的 "nulls are horizon-robust" 的科学效力；后续 4de45c27 的 E1 分支已自带 degenerate guard，反证该缺口是真实模式。
- 修复建议：把 phase_d_run 的 coverage guard 抽成共享函数并在 sweep 的 rel 分支复用（或在 sweep 侧同阈值 SystemExit）。
- 修复成本：低
- 状态：未修复（4de45c27d2000147915d8c78e441f9802f9d9298 仅给 E1 分支加了 guard，B/C/D 分支仍为 print-only）
