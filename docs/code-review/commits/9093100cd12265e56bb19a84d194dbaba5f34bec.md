## 对照参考
statsmodels 官方 `FEVD` 只支持 Cholesky 正交化，不支持 Pesaran-Shin 广义 FEVD（pystatsmodels Google Group 有官方确认），因此手工用 `ma_rep()` + `sigma_u` 计算广义 IR/FEVD 是社区标准做法，与 R `Spillover` 包 `g.fevd()`、PyPI `connectedness` 包及 MathWorks DY File Exchange 实现的归一化（行和为 1、总溢出=非对角均值）一致。公式实现正确。出处：groups.google.com（pystatsmodels）、rdocumentation.org、libraries.io、mathworks.com。

## 问题清单
### P2-1 泄漏防护测试空转（leakage guard 恒不触发）
- 描述：`tests/test_regime_global.py` 的 `test_leakage_guard` 中，n=600 价格 → 599 个收益率 → 滚动窗口 250，spillover 序列长度 = 599-250+1 = 350。守卫条件 `if len(spillover_baseline) > 395:` 恒为 False（350 < 395），导致"变异未来收益不得影响过去 spillover"这一核心防泄漏断言**从未执行**，测试空转通过。作者混淆了 spillover 序列的 iloc 位置与收益率序列位置（窗口止于收益率位置 395 对应 spillover.iloc[146]）。实现本身（`aligned.iloc[i-window:i]`）确为 past-only，但该项目以反泄漏为第一红线，安全网测试形同虚设属于实质性缺陷。
- 位置：`tests/test_regime_global.py:129`（`if len(spillover_baseline) > 395:`）
- 影响范围：`regime_global` 层的防泄漏回归保障失效；后续若有人改动窗口切片引入未来数据，测试不会报警。
- 修复建议：改为按收益率位置换算 `k = t - (window-1)`（如 t=395 → `iloc[146]`），并去掉长度守卫或断言 `len(spillover) == len(aligned) - window + 1` 先行验证序列长度。
- 修复成本：低
- 状态：未修复（`git log 9093100..main -- tests/test_regime_global.py` 无后续改动）

### P3-1 滚动循环裸 `except Exception` 无日志
- 描述：`except Exception: spillovers.append(float("nan"))` 把所有失败（含代码 bug、dtype 错误）静默转为 NaN，无任何警告日志；若某次 statsmodels 升级导致全部窗口抛错，输出全 NaN 且脚本无报错线索（仅打印 non-NaN 计数）。
- 位置：`src/aionis/features/regime_global.py:117-119`
- 影响范围：可观测性；极端情况整层特征静默失效。
- 修复建议：捕获时用 `warnings.warn` 或 structlog 记录首个异常（记录一次即可避免刷屏），并保留计数。
- 修复成本：低
- 状态：未修复

### P3-2 `pct_change()` 停牌填充行为随 pandas 版本漂移
- 描述：`pyproject.toml` 下限 `pandas>=2.0`；pandas <2.1 的 `pct_change()` 默认 `fill_method='pad'`，会把 CN 停牌后复牌首日的收益算成跨停牌累计收益，而 pandas 2.1+/3.0 默认不填充（复牌日为 NaN 被丢弃）。两种版本下 CN 市场收益的分布不同。仓库由 `uv.lock` 锁版本故仓内可复现，但下限声明与实际行为不匹配。
- 位置：`src/aionis/features/regime_global.py:36`（`wide_prices.pct_change()`）
- 影响范围：跨环境/跨版本重算 `regime_global_dy.parquet` 时结果不可比。
- 修复建议：显式传 `fill_method=None`（pandas≥2.1 语义）或在依赖声明中收窄版本窗口，并在 docstring 注明语义。
- 修复成本：低
- 状态：未修复
