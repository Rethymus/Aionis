## 问题清单
### P3-1 manifest 记录但不校验时间顺序，chronological 自相矛盾证据可被合法序列化
- 描述：`SplitTimeBoundaries` docstring 明言"train_end < test_start must hold (enforced by the caller, not here — the manifest records, does not validate, temporal ordering)"。于是一个 `validation_kind=chronological` 且 `train_end > test_start` 的矛盾 manifest 能通过校验并落盘——RD-02 要防的正是时序证据混乱。pydantic v2 的 `model_validator(mode="after")` 可在 manifest 层同时拿到 kind 与 boundaries，实现该约束成本很低。
- 位置：`src/aionis/eval/validation_manifest.py:107-160`（SplitTimeBoundaries docstring 与 ValidationManifest）
- 影响范围：证据审计链的下游消费者需自行复核时序一致性
- 修复建议：在 ValidationManifest 上加 mode="after" 校验：train_start<=train_end、test_start<=test_end；当 kind=chronological 时强制 train_end < test_start。
- 修复成本：低
- 状态：未修复（该文件此后无改动）

### P3-2 时区缺失的专用错误信息被自身 except 吞掉

- 修复成本：低
- 状态：未修复
