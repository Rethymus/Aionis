## 问题清单
### P2-1 `extract()` 的 `rule_table_path` 参数被静默忽略
- 描述：
  ```python
  load_path = rule_table_path or RULE_TABLE_PATH
  try:
      table = _load_rule_table()
  ```
  `_load_rule_table()` 无参且只读模块常量 `RULE_TABLE_PATH`；`load_path` 仅用于错误日志。docstring 声明该参数「Optional override path for rule table (for testing)」——实际任何传入自定义表路径的调用（如未来用变异表测试冲突逻辑）都会静默测试冻结表，得到误导性结论。当前测试未用该参数（全走真实冻结表），缺陷是潜伏的。
- 位置：`src/aionis/extraction/zero_llm_baseline.py:285-287`（配合 `:88-101` 的无参 `_load_rule_table`）
- 影响范围：所有期望用自定义表驱动 extract 的调用方/测试。
- 修复建议：`_load_rule_table(path: Path)` 接收 `load_path`；或删除该参数避免假 API。
- 修复成本：低
- 状态：未修复（该文件后续无 commit）

### P3-1 negation 关键词用子串匹配，窗口词含超串词时误否决
- 描述：`if keyword.lower() in window_text_lower:` —— "ease" 匹配 "release"/"please"，"cut" 匹配 "executed"，"hold" 匹配 "household"（fomc_increase 的否决词含 "hold"）。误否决方向是多余 abstain，与 abstain-by-default 哲学相容（只损失 recall），但与规则表 freeze_notes「whitespace-separated words」的词级定义不符。
- 位置：`src/aionis/extraction/zero_llm_baseline.py:150-156`
- 影响范围：zero-LLM 基线的召回率（精确率不受影响）。
- 修复建议：按空白分词后做整词比较（`keyword in window_words_set` 或 `re.search(rf"\b{re.escape(k)}\w*", ...)` 明确词干策略）。
- 修复成本：低
- 状态：未修复

### P3-2 table_sha256 对 yaml 重序列化结果取哈希，跨 PyYAML 版本不稳定
- 描述：`yaml.dump(table.model_dump(), sort_keys=True)` 后取 sha256[:16]——哈希对象是「pydantic 模型 → dict → yaml 默认样式」的产物，PyYAML 大版本变更默认流样式/字符串引用规则时，同一张表会得到不同 sha，破坏 provenance 可比性（uv.lock 钉版缓解）。直接对冻结文件字节取哈希更稳。
- 位置：`src/aionis/extraction/zero_llm_baseline.py:107-112`
- 影响范围：跨环境比较 table_sha256 的审计记录。
- 修复建议：`hashlib.sha256(RULE_TABLE_PATH.read_bytes())`（或读入的原始文本）。
- 修复成本：低
- 状态：未修复

### P3-3 重复实现 `text_hash` 而非复用 llm_client
- 描述：`source_text_hash=hashlib.sha256(text.encode("utf-8")).hexdigest()[:16]` 与 `llm_client.text_hash` 逐字相同——复制而非 import，若未来任一侧改算法（如加 salt/改长度）会静默分叉，破坏与 LLM 路径缓存键的可比性。
- 位置：`src/aionis/extraction/zero_llm_baseline.py:211`
- 影响范围：与 LLM 提取路径的 source_text_hash 一致性。
- 修复建议：`from aionis.extraction.llm_client import text_hash` 复用。
- 修复成本：低
- 状态：未修复
