## 对照参考
PIT 对齐的标准工具是 pandas 官方 `merge_asof`（按 ticker 分组、`left_on=date, right_on=filed_date, direction="backward"`，pandas.pydata.org/docs/reference/api/pandas.merge_asof.html）——一行即可实现「取 row_date 之前最近一次 filing」的语义。本实现的手写 query+dedup 既没有实现该语义，也没有留下任何可触发的校验。

## 问题清单
### P1-1 基本面 PIT 过滤为 no-op + filed_date 边界断言为死代码——「anti-leakage asserted」名不符实
- 描述：三重失效：(a) `fund_df.groupby("ticker")["filed_date"].max()` 得到的是**每 ticker 的全局最大** filed_date，`query("filed_date <= _max_filed")` 对所有行恒真——注释宣称的「只保留 filed_date <= row_date 的基本面」从未按 row_date 过滤；(b) 后续 `drop_duplicates([ticker, date], keep="last")` 只按 filed_date 排序去重，若同一 (ticker, date) 存在多条（含 filed_date > row_date 的未来申报）会保留 filed_date 最大者，恰好选中最未来的一条；(c) 合并列 `fund_cols` 显式排除 `filed_date`，故 `"filed_date" in panel.columns` 恒 False，`_assert_pit_boundary` 永不执行。commit subject 的「anti-leakage asserted」与 docstring 保证 #1 均无实现支撑。测试侧 `test_fundamentals_filed_date_pit` 只断言 `len(panel)>0`（fixture 的 filed_date 构造为 date-45d，恒合规），未负例覆盖。
- 位置：`src/aionis/features/panel_alignment.py:118-146`
- 影响范围：任何直接把未预对齐基本面喂给 `build_pit_panel(fundamentals=...)` 的调用方（未来 filing 直入特征且零告警）。实测生产路径（`scripts/track_b_materialize_panel.py`，main）以 `fundamentals=None` 绕开该分支、由上游 `_load_fundamentals` 预对齐，故**未污染已跑的真实数据**——但模块作为红线资产自带虚假安全保证。
- 修复建议：用 `pd.merge_asof(..., by="ticker", left_on="date", right_on="filed_date", direction="backward")` 重写；把 `filed_date` 保留进合并列使 `_assert_pit_boundary` 真正可触发；补「filed_date > row_date 的申报被丢弃」的负例测试。
- 修复成本：低
- 状态：未修复（模块此后无改动；生产路径绕行规避）
