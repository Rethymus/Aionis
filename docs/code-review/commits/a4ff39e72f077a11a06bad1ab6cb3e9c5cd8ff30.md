## 对照参考
新浪 `hq.sinajs.cn` 是中文量化圈事实标准的免费实时行情源（字段序 0=名称,1=今开,2=昨收,3=现价 与 akshare/easyquotation 等主流开源库的解析一致，github.com/akfamily/akshare）；其反爬要求 `Referer: finance.sina.com.cn` 也是社区共识做法。GBK→UTF-8 用 WHATWG `TextDecoder("gbk")` 符合标准 API（developer.mozilla.org）。缓存 key 不随后端版本隔离的问题对照 Cloudflare Cache API 文档（developers.cloudflare.com/workers/runtime-apis/cache/）——`cache.match` 只看 key，不看内容来源。

## 问题清单
### P2-1 切换后端未同步更换缓存 key，旧东财（含故障期空结果）缓存最长 24h 继续服务
- 描述：Sina 版仍用 `const cacheKey = new Request(\`https://cache.local/cn/${tickersParam}\`, ...)` —— 与东财版完全相同的 key。此前东财 502 期间/离场时段写入的缓存条目（TTL 30s~24h）在部署 Sina 版后继续命中并直接 `return hit`，新后端形同虚设，直到旧条目自然过期。
- 位置：`workers/prices/src/worker.js:95`（该 commit 版本）
- 影响范围：部署后最长 24h 内 CN 列可能仍显示旧东财数据或不更新。
- 修复建议：缓存 key 加入后端版本段（`/cn/v2/` 或 `/cn/sina/`）——即下一 commit 的做法；更稳妥的是把后端名纳入 key 模板避免每次换源手工记得 bump。
- 修复成本：低
- 状态：已在 c9e8f9fe 修复（key 升级为 `/cn/v2/`）
