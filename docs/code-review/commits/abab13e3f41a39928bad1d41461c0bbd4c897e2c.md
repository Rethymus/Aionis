## 对照参考
past-only 标准化（shift(1) 后 rolling）与 qlib `RobustZScoreNorm` 折内 fit 的防泄漏思想一致（qlib POC 报告 §2.3 本 repo 已实证 LEAKY vs CLEAN 差异）；FRED 观测缓存应按"序列+窗口"键控——本 repo 自己的 a8c7798（stakes_13d "window-keyed fetch cache + coverage guard"）就是同类修复的先例，FRED 官方 API 建议（fred.stlouisfed.org docs）也要求按 observation_start/end 显式分页。来源域名：fred.stlouisfed.org、github.com/microsoft/qlib。

## 问题清单
### P2-1 FRED 序列缓存键忽略 (start, end) 日期范围——扩展窗口时静默返回旧范围数据
- 描述：`pq = cdir / f"{series_id}.parquet"; if pq.exists(): return ...`——缓存命中路径完全不校验请求的 observation_start/end。先以短窗（如 end=2026-08）拉过 BAA/DGS10 后，再以更长 end 重建 regime 时，缓存命中静默返回旧短窗序列，宏观层末段悄无声息变 NaN/缺失，无任何告警。这正是 a8c7798 在 stakes_13d 上修过的同类缺陷（window-keyed cache + coverage guard）在 FRED 侧的复发。
- 位置：`src/aionis/features/regime_macro.py:90-97`（cache-hit 无范围校验）
- 影响范围：regime_macro.parquet 的时效性（跨月增量重建场景）；下游 conditional rank-IC 的宏观条件变量覆盖。
- 修复建议：缓存文件名带窗口（`{series_id}_{start}_{end}.parquet`）或命中时校验 `s.index.max() >= requested_end - buffer`，不足则 refetch（同 a8c7798 模式）。
- 修复成本：低
- 状态：未修复（regime_macro.py 至 main 无改动）
