## 对照参考
时间序列泄漏测试的成熟范式是 sktime 的 `temporal_train_test_split` 测试与 scikit-learn `TimeSeriesSplit`（scikit-learn.org）的「train 区间必须整体在 test 之前」不变量测试——本 oracle 的 `train evaluation_time <= test_start` + 严格 `<` 检查与之同构且更严格（多了 label 可得性维度）；「矩阵/注册表测试」若要真有回归力，成熟做法是让 parametrize 项指向可调用对象逐一执行（如 pytest 的 parametrize over test functions），而非文档式占位。

## 问题清单
### P2-1 回归矩阵登记了实现中不存在的 reason code，且对应测试从未验证它
- 描述：`test_regression_matrix_summary` 的参数表中为 overlap 场景登记 reason pattern `"train and test indices overlap"`，但 `assert_chronological_split`（`src/aionis/eval/cv.py:27-58`）根本没有 overlap 检查分支——它的 reason code 只有 `not chronological` / `length mismatch` / `empty train or test partition` / `out-of-bounds index` / `missing validation times` / `prediction_time is not strictly before test_start` / `evaluation_time extends beyond test_start`。而 `test_illegal_train_test_overlap_produces_stable_reason` 的测试体只做了 Python 集合交集自检（`train_set.intersection(test_set)`），从未调用 `assert_chronological_split`、从未断言该 reason code。实际行为：overlap 会被时间严格性检查间接捕获（共享行使 train_pt_max >= test_pt_min），但报出的是误导性的 "prediction_time is not strictly before" —— 文档与实现脱节，测试名承诺的「stable reason」无任何保障。
- 位置：`tests/test_chronological_oracle.py:405-426`（overlap 测试体）及 `:703-712`（矩阵登记项）
- 影响范围：审计者依据矩阵 believing overlap 有专属稳定 reason code；未来若时间检查逻辑变化，overlap 检测可能静默消失而矩阵依然全绿。
- 修复建议：要么在 `assert_chronological_split` 增加显式 `np.intersect1d` overlap 检查并让测试真正调用它，要么修正矩阵登记为实际 reason code 并重命名测试。
- 修复成本：低
- 状态：未修复（该测试文件与 cv.py 后续均无 commit）
