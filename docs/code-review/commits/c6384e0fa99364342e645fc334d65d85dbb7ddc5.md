## 问题清单
### P3-1 dsr_error 字段构造后被静默丢弃
- 描述：`except ValueError as e` 分支构造了 `d = {..., "dsr_error": str(e)}`，但紧接着 `dsr_by[nt] = {"dsr": float(d["dsr"]), "p_value": ..., "sr_star": ...}` 只取三个键，错误字符串无处落地——ledger 与控制台只看到 NaN，看不到"为什么 NaN"（denom_sq<=0 等）。commit message 声称"wrapped in try/except (symmetric with SPA/MCS)"，但 SPA/MCS 的 `spa_error`/`mcs_error` 键至少保留在返回 dict 中。
- 位置：`src/aionis/eval/strategy_returns.py:189-197`
- 影响范围：退化策略（极端 skew×sharpe）的诊断信息丢失，只影响可观测性，不影响数值结果。
- 修复建议：`dsr_by[nt]` 在 except 路径额外保留 `"error": str(e)` 键（正常路径无该键或为 None）。
- 修复成本：低
- 状态：未修复

### P3-2 脚本层丢失 spa_error/mcs_error
- 描述：`_append({... "spa": eval_out.get("spa"), "mcs_included": eval_out.get("mcs", {}).get("included") ...})`——当 `hansen_spa` 抛异常时键为 `spa_error`（`strategy_returns.py:231`），`eval_out.get("spa")` 得到 `None`，错误字符串既不进 ledger 也不打印（打印分支 `elif "spa" in eval_out` 同样不命中）。SPA/MCS 失败时账本里只剩 `"spa": null`。
- 位置：`scripts/strategy_eval_run.py:140-141`
- 影响范围：仅 exploratory 事件的诊断可观测性；数值路径不受影响。
- 修复建议：`_append` 时补 `"spa_error": eval_out.get("spa_error"), "mcs_error": eval_out.get("mcs_error")`，并在打印分支处理这两个键。
- 修复成本：低
- 状态：未修复
