## 对照参考
pandas 官方文档对 `groupby(...).idxmax()`/布尔掩码索引无异议；更相关的对照是 López de Prado `purgedcv`/`mlfinlab` 的 purged walk-forward 语义（本仓库 purgedcv 依赖即源于此）：purge 按 train 标签窗与 test 窗重叠剔除、embargo 在此之上加额外间隔。本 commit 的手写折分用「整月互斥」近似 purge（月末采样下最近 train 标签约在 test 预测日 resolving，实质重叠≈0），de facto 安全，但不再走 purgedcv 的机制化保证——与 AGENTS.md「PurgedGroupKFold + embargo」红线的机制化表述存在落差。

## 问题清单
### P2-1 embargo 参数被架空：`train_cutoff` 计算后死代码覆盖，文档仍声称 21-session embargo
- 描述：折循环内先计算 `train_cutoff = test_month_first_date - embargo_td` 并构造带 embargo 的 `train_mask`，**下一行立即被 `train_mask = panel["_year_month"] < test_calendar_month` 覆盖**——embargo 逻辑是死代码。最终 train = 测试月之前的所有整月，`embargo_sessions` 参数（签名、校验、docstring「Embargo: 21-session embargo between folds prevents label window overlap」、注释「train cutoff must be at least embargo_sessions before test start」）全部不再生效。月末采样 cadence 下最近 train 标签窗恰在 test 预测日附近 resolving，de facto 重叠≈0、安全，但这是**cadence 的巧合而非被声明的机制**；审计者读文档/前一个 mask 会误以为 embargo 被执行。若未来改为更密采样（如周频），此死代码会静默放行标签重叠。
- 位置：`src/aionis/eval/track_b_baseline.py:229-241`（该 commit 版本行号）
- 影响范围：Track B 全部折分的泄漏防护声明可信度；未来 cadence 变更时的静默风险。
- 修复建议：删除死的第一段 train_mask；要么真正执行 `train_cutoff`（剔除 cutoff 后的 train 行），要么在 docstring/ledger 修正声明为「月度整月互斥，等效 embargo ≥1 个日历月」。
