## 问题清单
### P1-1 fetch_realized_forward_returns 未 normalize 时间戳，live 路径揭示必然失败
- 描述：commit 行的 `predict_ts`/`target_t` 由 `session_close_ts(...).isoformat()` 生成（tz-aware、16:00 ET）；`fetch_realized_forward_returns` 仅 `tz_localize(None)` 不 `.normalize()`，得到 `2026-07-31 16:00:00`，而价格 parquet 索引是 midnight 日期 → `predict_dt not in prices.index` 恒真 → 返回空帧 → `reveal_and_score_forward_month` 对每臂返回 "no_valid_returns"。测试全部用 `"2026-07-01"` 这类纯日期字符串，恰好绕开了该缺陷（实测 pandas 语义已确认：`ts in idx == False`、`ts.normalize() in idx == True`）。
- 位置：`src/aionis/eval/forward_score.py:47-53`
- 影响范围：E3 前瞻 reveal/score 的 live 链路——真实 commit 行时间戳下永远无法揭示，IC 累积为空。
- 修复建议：`predict_dt = pd.Timestamp(predict_ts).tz_localize(None).normalize()`（两处），或统一在 ledger 写入侧即用日期。
- 修复成本：低
- 状态：未修复（main 上该函数原样保留；后续 AUD-06 readiness gate 不覆盖此函数）

### P2-2 I1 门的 tz 混用比较在 naive target_t 下会抛 TypeError
- 描述：`now_dt = pd.Timestamp.now(tz=timezone.utc)`（aware）与 `target_dt = pd.Timestamp(target_t)`（若为 naive 字符串，如测试与某些手工调用）比较 `now_dt < target_dt` 直接抛 `TypeError: Cannot compare tz-naive and tz-aware timestamps`；live 路径（aware target）成立，但契约脆弱、错误信息不友好。
- 位置：`src/aionis/eval/forward_score.py:117-121`
- 影响范围：任何以 naive target_t 调用 reveal 的调用方/运维脚本。
- 修复建议：比较前统一 `_ensure_et` 式规范化（aware 化或同时 naive 化），失配抛带上下文的错误。
- 修复成本：低
- 状态：未修复
