## 问题清单
### P3-1 模块 docstring 的 lane 列表与 LANE_ROLES 键不一致
- 描述：docstring 写 `executor / verifier / code-reviewer / qa-tester / supervisor`，但实际 CLI choices 是 `executor / verifier / reviewer / e2e / supervisor`（无 `code-reviewer`、`qa-tester`，那是 OMC agent 名而非 lane 名）。用户按 docstring 传 `--lane qa-tester` 会直接 argparse 报错。
- 位置：`scripts/orchestrate_dispatch.py:8`（模块 docstring 第 3-5 行）
- 影响范围：CLI 使用者（仅文档误导，argparse 会兜底报错）。
- 修复建议：docstring 改为与 `LANE_ROLES` 键一致，或注明 OMC agent 名映射（code-reviewer→reviewer、qa-tester→e2e）。
- 修复成本：低
- 状态：未修复

### P3-2 `_split_paths` 不剥离结尾标点，token 可能带尾点
- 描述：`_split_paths` 仅 strip 空白与反引号；任务文件"允许修改"字段若以句号结尾（如 `tests/test_foo.py.`），产出的 allowed_files token 带尾点。测试 `test_json_contract_is_deterministic_and_supervisor_is_opus` 断言 `["scripts/foo.py", "tests/test_foo.py."]` 反而把该瑕疵固化进了契约。
- 位置：`scripts/orchestrate_dispatch.py:107-114`
- 影响范围：dispatch 契约 L5 层的 evidence 路径可能带脏字符（对 LLM worker 影响极小）。
- 修复建议：token 末尾追加 `clean = clean.rstrip("。.;；,，")` 一类标点剥离，并同步修测试 fixture。
- 修复成本：低
- 状态：未修复
