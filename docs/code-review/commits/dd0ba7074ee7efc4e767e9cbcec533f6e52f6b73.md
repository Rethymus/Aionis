## 对照参考
EDGAR daily index 的五字段结构（Company Name | Form Type | CIK | Date | Filename）与 SEC 官方 "Accessing EDGAR Data" 文档一致，本 commit 的 2+ 空格分词 + 表单过滤 + accession 提取与社区通用解析做法（kaichen.work 教程、pandas read_table 方案）同型；重试/退避走 requests+策略层（urllib3 Retry 风格）。出处：sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data。

## 问题清单
### P1-1 合并逻辑在 CI 上是死代码 —— 面板在目标环境并未解冻
- 描述：`export_smart_money` 开头 `cache_files = glob.glob("data/cache/efts_13d_*.json")`，为空即 `return`（本地-only 的 EFTS 历史缓存在 CI 永不存在）；而本 commit 新增的 `sc13d_daily_aggregate.json` 合并块位于该早退之后。因此 daily cron 里 daily-index 数据永远进不了 smart_money.json —— commit 的核心目标在 CI 上并未达成，仅因作者本地有 efts 缓存而"看起来成功"。后续 5ea6649 的 message 直接确认："smart_money.json froze at 2026-08-07: the export hard-required the local-only efts_13d_*.json ... and SKIPped entirely on CI"。
- 位置：`scripts/export_terminal_data.py:912-921`（早退）与 `:946-962`（合并在早退之后，该 commit 版本）
- 影响范围：daily cron 每天抓到的 13D 数据被丢弃，面板冻结在作者最后一次本地导出的 2026-08-07，持续约 4 天。
- 修复建议：合并块应不依赖 efts 缓存存在；或采用 retain-and-refresh（保留已提交 JSON 的历史聚合并仅刷新近端）——正是 5ea6649 的做法。
- 修复成本：中
- 状态：已在 5ea6649 修复

- 位置：`scripts/export_terminal_data.py:968-970`（该 commit 版本）
- 影响范围：web deploy 中断；smart-money 页 active_filers 榜单消失。
- 修复建议：排名应对全部真实 filer 行统计（去掉 [:300] 截断）或按来源分组；空列表时导出 `[]: SmartMoneyFiler[]` 显式类型。
- 修复成本：低

### P2-1 逐天失败静默吞掉，零日志可观测
- 描述：`fetch_recent_13d_daily` 中 `except Exception: cur += timedelta(days=1); continue` —— 单日 403/429 跳过是合理的韧性设计，但没有任何 print/logging 记录哪一天失败、为何失败；若 UA 被 EDGAR 长期限流，会静默产出带缺口的数据，且每日重跑反复撞同一批失败日。
- 位置：`src/aionis/ingest/stakes_13d_daily_index.py:128-135`（该 commit 版本）
- 影响范围：backfill 数据质量无观测手段；cron 日志里看不到抓取缺口。
- 修复建议：记录 `logging.warning("daily-index fetch failed %s: %r", cur, exc)` 并在结束时汇总失败天数；失败比例超阈值时非零退出提醒 cron。
- 修复成本：低
- 状态：未修复（该文件此后无改动）

### P3-1 节假日/404 日永不缓存，每日重打
- 描述：`fetch_daily_crawler_index` 仅在成功时写缓存；EDGAR 联邦假日无 crawler.idx（404→异常→跳过），这些日期每次运行都被重新请求（每年 ~10 天 × ≥2s 间隔）。
- 位置：`src/aionis/ingest/stakes_13d_daily_index.py:62-75`
- 影响范围：每日 cron 的少量无效请求与耗时。
- 修复建议：404 时写一个空哨兵文件缓存"该日无索引"。
- 修复成本：低
- 状态：未修复

### P3-2 杂项：跨模块私有导入 + 占位 UA + 无 accession 去重
- 描述：`from aionis.ingest.universe import _policy_get` 引用私有符号（应提升为共享 `http_policy` 公共 API）；`_UA = "...contact@example.com"` 占位联系邮箱（SEC fair-access 偏好真实联系方式，仓库既有惯例如此）；EFTS 与 daily 合并未按 accession 去重（当前窗口不重叠故无实际重复，`--start` 早于 2024-12-17 时会产生重复行）。

- 修复建议：`_policy_get` 公共化；UA 换真实邮箱；合并时按 `accession` 去重。
