## 问题清单
### P3-1 分箱示例与伪代码存在 off-by-one 不一致，削弱「机械实现」前提
- 描述：三处不自洽：(a) §4 示例称「Quintile edges (20%, 40%, 60%, 80%)」却给出 5 个值 `[0.00, 0.012, 0.019, 0.022, 0.04]`（完整五分位应含 6 个切点含 0%/100%）；(b) 示例 digitize 结果（0.01→bin 1、0.02→bin 3、0.05→bin 5）无法由声明的 `np.digitize(return, edges[1:]) - 1` 从这组 edges 推出；(c) §6 伪代码正常分支 `np.digitize(return_value, bin_edges[1:])` 对最低 bin 返回 0，而低越界钳制分支显式 `relevance = 1`——同一段伪代码内 0 基与 1 基并存。决策包声称 Engineer 将「机械实现（no self-selection）」，示例不一致会迫使实现者自行裁决索引约定，恰是本包要消除的自由度。
- 位置：`reports/design/2026-08-01-rd15-rank-objective-contract.md` §4 示例（约 L190-210）与 §6 `transform_with_clamp`（约 L280-320）
- 影响范围：后续 ea335c82 实现的正确性锚定；读者对分箱语义的理解。
- 修复建议：统一为一种索引约定（如 relevance ∈ 1..n_bins，正常分支 `np.digitize(x, edges[1:]) + 1` 或等价），并修正示例 edges 数量。
- 修复成本：低
- 状态：待人工复核（需对照 ea335c82 实现确认最终采用的约定）

### P3-2 不变量测试伪代码用未播种的 `np.random.permutation`
- 描述：INVARIANT 1（月置换不变性）的测试伪代码 `perm_idx = np.random.permutation(len(returns))` 未固定 seed，与项目「所有 seed 固定为 0」的 H6 纪律相悖；若 Engineer 照抄，测试含未固定随机性。
- 位置：`reports/design/2026-08-01-rd15-rank-objective-contract.md` §7 INVARIANT 1 测试
- 影响范围：后续实现测试的可复现性。
- 修复建议：改为 `np.random.default_rng(0).permutation(...)`。
- 修复成本：低
- 状态：待人工复核（在 ea335c82 实现中核查是否已播种）
