## 对照参考
- urllib3 `Retry` 以 `DEFAULT_BACKOFF_MAX = 120` 封顶计算退避与 Retry-After（urllib3.readthedocs.io reference/urllib3.util.html；源码 pradyunsg.me/furo/_modules/urllib3/util/retry）；本实现的 `RetryPolicy.delay` 返回 `max(configured, retry_after)` 无任何上限——一个异常服务器返回 `Retry-After: 86400` 会让 cron/CI 任务挂死一天。
- tenacity `wait_exponential_jitter`（tenacity.readthedocs.io）演示了成熟退避默认带 jitter；本实现无 jitter（单一 host + 串行锁下影响小，P3 级）。
- 审计报告的证据分级（F/I/H/D）与"当场运行 uv run pytest 发现 exit 2"的诚实自曝是研究治理的最佳实践。

## 问题清单
### P2-1 RetryPolicy.delay 遵循 Retry-After 无上限，恶意/异常头可无限挂起抓取任务
- 描述：`return max(configured, _retry_after_seconds(headers, wall_time=wall_time))` —— `_retry_after_seconds` 解析数字或 HTTP 日期后直接返回秒数，无 ceiling；`HttpRequestPolicy.request` 对该值无条件 `self._sleep(...)`。urllib3 的对应实现以 120s 默认封顶。
- 位置：`src/aionis/ingest/http_policy.py:150-160`
- 影响范围：所有接入 `_policy_get` 的抓取路径（EDGAR/FRED/Tiingo/Alpaca/GitHub raw 等）在收到超大 Retry-After 时长时间睡眠，CI/cron 无超时保护。
- 修复建议：`RetryPolicy` 增加 `max_delay`（默认如 120s）：`return min(max(configured, retry_after), self.max_delay)`。
- 修复成本：低
- 状态：待人工复核（后续 6085e92 "close remaining transport policy gaps" 是否补上限需在该 commit 复核）

### P3-1 进程级 HTTP 策略单例 `_policy_get` 放在 universe.py，六个模块跨层导入其私有符号
- 描述：`ingest/universe.py` 定义 `_HTTP_POLICY` 与 `_policy_get`，而 `ingest/market|fundamentals|stakes_13d|stakes_13d_efts|events|cik_resolver|event_text` 以及 **features**/macro_surprise.py 全部 `from aionis.ingest.universe import _policy_get` —— universe（成员资格模块）成为全仓 HTTP 传输所有者，且依赖方向含 features→ingest 私有符号。
- 位置：`src/aionis/ingest/universe.py:37-56`
- 影响范围：模块边界与未来拆分成本（单例共享本身正确——host 间隔全进程生效）。
- 修复建议：把实例与便捷 GET 上移到 `http_policy.py`（如 `get_shared_policy()`）。
- 修复成本：低
- 状态：未修复

### P3-3 phase_b_fetch 删除 Tiingo 健康探测后，429 场景退化为每符号重试慢路径
- 描述：原探测（429 时直跳 Alpaca，避免 ~25s/符号 × 多小时）被删除，理由是策略层已有有界重试；但策略层的线性退避在 429 下仍会为每个符号付出完整重试时长，批量符号下总时长与被删除的探测所防的场景相同。
- 位置：`scripts/phase_b_fetch.py:58-70`
- 影响范围：冷缓存全量重建的墙钟时间。
- 修复建议：恢复一个经 `_policy_get` 的廉价健康探测或对 429 快速失败切换 provider。
- 修复成本：中
- 状态：待人工复核
