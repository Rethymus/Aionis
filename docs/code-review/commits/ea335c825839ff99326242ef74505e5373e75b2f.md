## 问题清单
### P2-1 unseen-month 回退边用「各月 edges 的逐点均值」而非冻结 spec 的「全训练集合并分位数」，且 fit 内真正的 pooled edges 是死代码
- 描述：冻结决策包（e50d6748）规定「Months with NO train samples: use pooled quantile edges across all train months」。实现中 `fit_monthly_bins` 确实计算了真正的合并分位数 `pooled_edges = np.quantile(valid_returns, ...)`，但只用于「该月全 NaN」分支，从不随 `fitted_bins` 返回；而 `transform_to_relevance` 对未见月份另行构造 `pooled_edges = np.mean(all_edges, axis=0)`（各月分位边的逐点算术平均）。两者数学上不同：均值-of-edges 会向月份均值收缩，无法反映跨月收益分布的尾部。在 walk-forward 场景下测试月永远不在训练折 → 全部走这条偏差路径，属于承载性偏差且无测试锚定（`test_transform_to_relevance_unseen_month` 只断言 relevance ∈ [1,5] 与 reason code，不校验边值）。无泄漏（两种定义都只用训练折量），但与 owner 冻结的 spec 不一致、且实现内部两处「pooled」一词指两个不同对象。
- 位置：`src/aionis/eval/ranking_contract.py:158-161`（fit 内 pooled 死代码）与 `:235-237`（transform 的 mean-of-edges）
- 影响范围：所有 walk-forward 使用该合约的训练（后续 Track B rank 管线）：测试月相关性标签的分布形态与 spec 预期不同。
- 修复建议：`fit_monthly_bins` 返回 `(fitted_bins, pooled_edges)` 或在 dict 中加入哨兵键，transform 直接复用真合并分位数；补一条断言 unseen 月边 == 合并分位数的测试。
- 修复成本：低
- 状态：未修复（5e2ce6d 仅修单行月崩溃，未动该偏差）
