## 对照参考
- Wilson 区间：公式实现与 statsmodels `proportion_confint(method='wilson')` 一致（statsmodels.org；Wikipedia Binomial proportion confidence interval）；注意 Wilson 区间在 p=0/1 时数学上良定义且恰恰是推荐场景，本实现选择返回 None 属刻意保守（已在 docstring 声明），非公式错误。
- macro-F1 约定：scikit-learn `f1_score` 官方文档（scikit-learn.org）明确「F1 is by default calculated as 0.0 when there are no true positives」——即 tp=0 但 fp/fn>0 的类按 0 计入 macro 平均（zero_division=0 默认）；本实现将该层排除，偏离标准约定（见 P2-1）。

## 问题清单
### P2-1 tp=0（fp/fn>0）的层被排除出 macro-F1，估计系统性偏乐观
- 描述：F1 判定用 `(precision + recall) > 0` 作为可定义条件：
  ```python
  if precision is not None and recall is not None and (precision + recall) > 0:
      f1_value = 2 * precision * recall / (precision + recall)
      valid_strata.append(stratum)
  else:
      warnings[stratum] = "undefined_f1"
  ```
  当 tp=0、fp>0、fn>0 时 precision=0、recall=0，sum=0 → 该层被标记 `undefined_f1` 并从 macro 平均中剔除。但按标准定义 F1 = 2TP/(2TP+FP+FN) = 0（sklearn 默认 zero_division=0 即如此，0 计入 macro 平均），并非未定义。模型完全漏掉某事件类型的层会被静默剔除，使 `f1_estimate` 与 bootstrap CI 双双上偏。同样的问题在 bootstrap 复制内更常见：某次重抽样出现 tp=0 时该层从该次复制的均值中被剔除（而非计 0），不同复制平均的层数不同，百分位区间进一步失真。真正未定义的情形只有 tp=fp=0 或 tp=fn=0（分母为零）。
- 位置：`src/aionis/extraction/eval_uncertainty.py:217-221`（点估计）及 `:277-283` 附近的重抽样路径（`resample_precision + resample_recall > 0` 同款判断）
- 影响范围：`stratified_bootstrap_f1` 的所有调用方——extraction 评估报告中的 macro-F1 点估计与置信区间在存在「全漏层」时偏乐观。
- 修复建议：改用调和安全形式 `f1 = 2*tp / (2*tp + fp + fn)`，仅当 `tp+fp==0` 或 `tp+fn==0`（真分母为零）时视为未定义；bootstrap 复制内对 tp=0 层计 0 而非剔除。
- 修复成本：低
- 状态：未修复（该文件后续无 commit）

### P3-1 `_z_critical` 注释自相矛盾且未用更直接的 norm.ppf

### P3-2 纯 Python bootstrap 循环可向量化
- 描述：`for i in range(n_resamples):` 内逐层 `rng.multinomial(n, p)` 再用 Python 浮点算 F1；默认 10000 次重抽样 × 每层一次调用。numpy 的 `rng.multinomial(n, p, size=n_resamples)` 可一次生成全部计数，F1 用数组运算，速度可提升 1-2 个数量级（离线场景影响有限）。
