## 对照参考
Python 官方 json 文档（docs.python.org/3/library/json.html）与 psf/requests#5767、evanhahn.com：`json.dumps` 默认 `allow_nan=True` 会输出 `NaN` 裸 token，**违反 RFC 8259**，浏览器 `JSON.parse()` 直接抛 SyntaxError——本 commit 的 `json.dumps(site_data)` 未做 NaN→null 清洗（P2-1）；同仓库 33035c3（2026-08-07）为 `ic_monthly.json` 修过完全相同的 bug 类。plotly CDN（cdn.plot.ly）为官方分发方式，版本已钉 2.35.2，但对中文受众的可达性不如镜像（P3-2）。

### P2-1 `track_b_data.json` 导出未做 NaN 清洗，可产出非法 JSON
- 描述：`site_path.write_text(json.dumps(site_data, indent=2), encoding="utf-8")`——`ic_series` 由 `{str(k): v for k, v in rt.ic_series.items()}` 直接导出；若任一月 IC 为 NaN（横截面不足、全同秩等路径），`json.dumps` 默认输出 `NaN` 裸 token，浏览器 `JSON.parse` 抛错，站点 IC 图整体失效（且 GitHub Pages 上无报错界面，只有空图）。仓库已在 33035c3 承认并修复过同类问题（ic_monthly.json），但本文件未同步处理。
- 位置：`scripts/track_b_a_run.py:89-106, 131-133`（该 commit 版本）
- 影响范围：站点 IC 月度序列图的可用性（数据依赖路径）。
- 修复建议：导出前递归把 NaN/Inf 转 `null`，或 `json.dumps(..., allow_nan=False)` 快速失败 + 预清洗。
- 修复成本：低
- 状态：未修复（main 上 track_b_a_run.py 仍是裸 dumps；33035c3 只修了 ic_monthly.json）
