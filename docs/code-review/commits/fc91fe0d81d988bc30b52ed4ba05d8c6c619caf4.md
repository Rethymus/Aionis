### P3-1 commit message 对 timetohigh 的冒烟解读是错的（记录层面的语义污染）
- 描述：commit message 写 "timetohigh_63d mean=0.40 (avg stock ~40% off its quarterly high)" —— 把 0..1 的时间位置指标读成了价格回撤幅度。实际语义是"滚动最高点出现在窗口内的相对位置"（0=当前即是高点，1=高点在窗口最前端），UI 标签（"0=创新高，1=在低点"）是对的，但 commit 叙事会给日后追溯者留下错误解释。
- 位置：commit message（实现见 `src/aionis/features/qlib_close_factors.py:75-79`）
- 影响范围：仅记录/沟通层面；代码与 UI 正确。
- 修复建议：无代码改动必要；在 state/handoff 更正一句即可。
- 修复成本：低
- 状态：未修复

### P3-2 rolling.apply Python 回调是全面板导出的性能短板
- 描述：`close.rolling(w).apply(lambda x: ..., raw=True)` 每行一次 Python 调用；1.17M 行面板 × 2 窗口 ≈ 470 万次回调，在每日 CI 的 export_themes 里徒增数十秒。可用 `(close == hi)` 的 cummax/cumsum 技巧或 numpy 滑窗向量化。
- 位置：`src/aionis/features/qlib_close_factors.py:75-79`（该 commit 版本）
- 影响范围：daily cron 时长（非功能）。
- 修复建议：向量化 argmax 位置计算。
- 修复成本：中
- 状态：未修复

### P3-3 死代码 reindex 守卫 + IMAX 平盘并列时取首个极值
- 描述：`enriched.reindex(panel.index) if panel.index.equals(enriched.index) else enriched` 两分支都是恒等操作（相等时 reindex 为自身，不等时原样返回）——纯死代码。另外 `np.argmax` 取首个最大值：完全平盘的窗口会得到 timetohigh=1.0（"高点最久远"），对"从未动过"的股票语义误导。
- 位置：`src/aionis/features/qlib_close_factors.py:110-111、75-79`（该 commit 版本）
- 影响范围：可读性/平盘极端情形的展示语义。
- 修复建议：删除 reindex 行；并列最大值时取最后一次出现（`len(x)-1-argmax(x[::-1])`）更符合"最近触及高点"直觉。
- 修复成本：低
- 状态：未修复
