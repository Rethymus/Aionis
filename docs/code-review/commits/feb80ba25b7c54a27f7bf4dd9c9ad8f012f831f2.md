## 问题清单
### P2-1 危险面检查只扫"禁止修改"黑名单，白名单放行冻结管线不受检查
- 描述：`check_dangerous_commands` 仅对 `fields.get("禁止修改")` 匹配 `DANGEROUS_PATTERNS`（phase_/strategy_/forward_ 等）。一个任务写 `允许修改: scripts/phase_d_run.py`（白名单直接放行确认性 runner）时零告警；而写 `禁止修改: phase_*.py`（保护性声明，反而是好事）却触发 `DANGEROUS_COMMAND_DECLARED`。RD-01 的目标是"减少弱模型越界"，越界恰恰发生在允许列表里——检查方向与风险方向相反了一半。
- 位置：`scripts/check_task_contracts.py:113-128`
- 影响范围：依赖该 linter 输出做任务分发的编排层会漏掉最高风险的一类任务
- 修复建议：对 `允许修改` 同样匹配 `DANGEROUS_PATTERNS` 并输出更高级别的 reason code（如 `DANGEROUS_SURFACE_ALLOWED`）；现有黑名单命中可降级为信息性 code 并改名以免误导。
- 修复成本：低
- 状态：未修复（该脚本此后无改动）

### P3-1 字段解析匹配全文任意"- key: value"行，必填字段检查可被正文伪满足
- 描述：`parse_task_file` 对整个文件逐行做 `- key: value` 匹配，不限元数据头部；正文中出现的 `- 状态: xxx`、`- 标题: yyy` 等普通列表项会填充 fields，使头部实际缺失的必填字段被误判为存在（假阴性）。
- 位置：`scripts/check_task_contracts.py:73-90`
- 影响范围：MISSING_REQUIRED_FIELD 检查的可信度
- 修复建议：只在第一个二级标题/分隔线之前的元数据块解析，或要求键必须属于已知键集合。
- 修复成本：低
- 状态：未修复

### P3-2 输出格式细节不一致与 CSV 未转义
- 描述：`MISSING_REQUIRED_FIELD:{field}|{path}` 只有两段，而其余 reason 是三段 `code|path|detail`，CSV 模式下 reason_code 列混入字段名；detail 含逗号时 CSV 列会错位（未做 quoting）。另有死代码 `fields.get("状态", fields.get("状态", ""))`、`fields.get("禁止修改", fields.get("禁止修改", ""))`（内外表达式完全相同）。
- 位置：`scripts/check_task_contracts.py:99-104`、`137-140`、`167-179`、`204-207`
- 影响范围：机读消费（CSV）与维护可读性
- 修复建议：统一三段格式；CSV 用 csv.writer 自动转义；删除重复 get。
- 修复成本：低
- 状态：未修复
