# Aionis Orchestration Protocol — operational spec

> This document operationalizes [`../WORKFLOW.md`](../WORKFLOW.md) §8 (single Orchestrator +
> on-demand specialists) and §10 (6-layer context). It does NOT re-express the constitution; it
> binds OMC primitives + Aionis anti-leakage guardrails into a reproducible wave procedure.
> Decision of record: [`../decisions/ADR-012-orchestration-protocol.md`](../decisions/ADR-012-orchestration-protocol.md).

## 1. Lane model

| Lane | Agent / model | Frequency | Reads | Writes | Stop |
|------|---------------|-----------|-------|--------|------|
| **Orchestrator** | opus (this session) | per wave | `state/*`, `tasks/active/` | `state/handoff.md`, task `状态` line, dispatch contracts | wave acceptance gate passed |
| **Supervisor (监工)** | opus — `architect` / `critic` | **low-freq, gates only** | decision/freeze/escalation artifacts | decision packet, review verdict | verdict emitted |
| **Worker** | sonnet `executor` / haiku `general-purpose` | per task | ONE dispatch contract (§3) | only the task's `允许修改` files | task acceptance met |
| **Verifier (验收)** | sonnet/haiku `verifier` | per task, independent | code + command output + data — NEVER engineer prose | `PASS`/`FAIL`/`BLOCKED` + evidence | objective verdict |
| **Reviewer** | sonnet `code-reviewer` | per task, diff-only | task spec + `git diff` + test results | `APPROVE`/`REQUEST CHANGES`/`BLOCKED` | blocking issues listed |
| **E2E** | sonnet `qa-tester` / `test-engineer` | pre-push / real wave | full hermetic suite + frozen-surface audit | e2e report | green suite + ledger 0-diff |

The Orchestrator and the Supervisor are both opus but are **different roles**. The Orchestrator runs
the wave (read state → slice → dispatch → gate → sediment). The Supervisor is invoked **only at
decision / freeze / escalation gates** — that is the "low-frequency monitoring" (监工). Do not route
every worker step through the Supervisor; that defeats the token economy (WORKFLOW §11).

## 2. Wave procedure

```
freeze → slice → dispatch contract → worker (serialized) → verify → review → e2e → sediment
```

1. **Freeze** — confirm the task spec is frozen (WORKFLOW §6). Owner-commissioned tasks only — per
   Wave-B precedent, pre-authorize in the task `状态` line *before* dispatch.
2. **Slice** — Planner ensures `Size ∈ {S, M}`; `L` is forbidden to dispatch (split first).
3. **Dispatch contract** — Orchestrator runs
   `scripts/orchestrate_dispatch.py --task <file> --lane <lane>` to emit the denoised 6-layer
   context (§3). Any blocking lint reason → abort dispatch.
4. **Worker** — spawn ONE `executor` (sonnet) per task via the Agent tool with `model="sonnet"`
   (the session carries `[1m]`, so a tier alias is mandatory). Writers are SERIALIZED — never ≥2
   concurrent writers in the shared tree (parallel-writer race; memory `aionis-parallel-writer-race`).
   Read-only preflights MAY run ≤2 concurrent.
5. **Verify (验收)** — independent lane runs the deterministic acceptance gate (§5) and returns
   PASS / FAIL / BLOCKED. The Verifier trusts only code / command output / data, never the worker's prose.
6. **Review** — `code-reviewer` inspects the diff only (WORKFLOW §16). Max 2 fix rounds, then BLOCKED.
7. **E2E** — pre-push: full hermetic `uv run pytest -q`, `uv run ruff check`, frozen-surface audit,
   `runs/ledger.jsonl` 0-diff.
8. **Sediment** — Orchestrator writes the structured summary into `state/handoff.md` + the task
   `状态` line (incremental update, not re-summarization — WORKFLOW §11.5 anti-collapse).

## 3. Dispatch contract anatomy (6 layers — WORKFLOW §10)

Generated by `scripts/orchestrate_dispatch.py`. Blank template: `tasks/templates/DISPATCH-CONTRACT.md`.

1. **Stable rules** — Aionis anti-leakage guardrails (§4) + the lane's role boundary.
2. **Role** — "You are the `<lane>`; do only `<lane>`'s job; stop when `<stop>`."
3. **Task** — task file path + the frozen `验收标准` + `必须运行的测试`.
4. **State** — `state/current.md` pointer (not full body) + the relevant `state/handoff.md` slice.
5. **Relevant evidence** — the specific files/functions the task touches (by `path:lines`), not the repo.
6. **Output format** — structured result: files changed / tests / evidence / risks / next-action.

**Forbidden in a dispatch** (denoising): full chat history, stale rejected options, whole repo,
unfiltered logs, completed-task bodies, repeated rule text. Rationale: WORKFLOW §10 + §13
(anti-drift — one expression of each fixed rule).

## 4. Anti-leakage guardrails (binding on every worker dispatch)

- **No real runs**: workers MUST NOT execute real network / LLM / forward / confirmatory / strategy /
  horizon scripts. Offline / hermetic only.
- **No frozen surfaces**: prereg / ADR / config / `runs/ledger.jsonl` / results / data / forward are
  read-only to workers. `config_committed` BEFORE result; `runs/ledger.jsonl` 0-diff is a hard gate.
- **Serialized writers**: one Engineer per dispatch message, or isolate via a git worktree
  (OMC `TEAM-WORKTREE-MODE`).
- **Concurrency cap**: ≤2 concurrent dispatches (proxy `[1210]` cap); single retry on transient
  `[1210]` Reviewer errors.
- **Model tiers by risk** (not by task name): opus = analysis / decision / hard review; sonnet =
  standard code; haiku = mechanical. Reversible + mechanical → haiku; irreversible / high-impact → opus.

## 5. Acceptance (验收) gate

A task is NOT done until ALL hold (mirrors `../CLAUDE.md` "Definition of done"):

1. Acceptance criteria met; specified tests pass — **deterministic evidence, not prose**.
2. No `TODO` / `test.skip` / `.only` / stub / unimplemented branch (these are blockers).
3. `runs/ledger.jsonl` 0-diff unless the task is itself a ledger-write (then `config_committed` first).
4. Frozen-surface audit empty; no `data/` / `*.parquet` / `.env` staged.
5. Independent Verifier PASS + Reviewer APPROVE recorded in the task `状态` line.

## 6. When to dispatch vs direct-write vs escalate

- **Direct-write** (Orchestrator, no dispatch): trivial ops, single-command clarifications, and the
  OMC allow-list (`~/.claude/**`, `.omc/**`, `.claude/**`, `CLAUDE.md`, `AGENTS.md`).
- **Dispatch** (worker lane): any multi-file change, refactor, feature, bug fix, or test addition.
- **Supervisor gate** (opus, low-freq): architecture decisions, hard bugs, high-risk review,
  freeze/amendment proposals, BLOCKED escalations after 2 failed fix rounds.

## 7. Issue orchestration = task files

Per ADR-012, local `tasks/*.md` files ARE the issues (zero GitHub surface). Each task file carries
ID / status / priority / size / risk / acceptance / allowed+forbidden files / required tests — the
full ticket semantics. Cross-session "issue state" = the task `状态` line + `state/handoff.md`.
The dispatch helper reads issue state from the task file and validates it via the RD-01 contract
checker before any dispatch — an invalid issue cannot be dispatched.

## 8. Operability notes (known harness behaviors)

Observed in the inaugural ORCH-01 wave (2026-08-03); binding for future waves:

- **Synchronous subagents return via `idle_notification`, not inline.** A `run_in_background: false`
  Agent call spawns successfully, but the Orchestrator receives an `idle_notification` rather than the
  worker's final report. Recovery: reclaim the worker's L6 structured result via `SendMessage(to:
  <name>)`. Do NOT end the Orchestrator turn before reclaiming (a completed child cannot notify a
  parent whose turn has ended).
- **Code-producing lanes: recover from repo state, never from worker prose.** A worker may go idle
  without sending its L6 result; the deliverable lives in the repo (`git diff` + the specified tests).
  The Orchestrator's acceptance evidence is the deterministic gate (§5), not the worker's self-report.
- **Prose-only lanes (reviewer) have no repo artifact.** If a reviewer goes idle without delivering its
  verdict, reclaim once via `SendMessage`. If it idles again, STOP (WORKFLOW §17 — two identical
  failures) and proceed on the Orchestrator's independent deterministic verification + line-by-line
  diff review, with the reviewer-lane deviation explicitly disclosed in the task `状态` line and the
  commit message. Do NOT infinite-loop ping.
