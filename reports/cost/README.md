# Evaluation Report Cost Metadata (RD-07)

## Purpose

This section defines the cost metadata contract for the evaluation report generated by `src/aionis/extraction/eval_report.py` (task RD-07).

## Report Structure

The evaluation report is a versioned JSON file combining:

- **Quality metrics**: From `eval_metrics.py` (RD-06): precision, recall, F1, coverage, abstention, per-field accuracy, etc.
- **Provider metadata**: Provider name, model ID, prompt version, schema version
- **Execution metadata**: Cache hit rate, token counts, cost, latency (all optional)

## Cost Metadata Fields

The `execution` section of the report contains the following fields:

| Field | Type | Description |
|-------|------|-------------|
| `cache_hit_rate` | `float \| null` | Cache hit rate (0.0 to 1.0) if caching was enabled |
| `total_tokens` | `int \| null` | Total tokens processed (prompt + completion) |
| `prompt_tokens` | `int \| null` | Prompt token count |
| `completion_tokens` | `int \| null` | Completion token count |
| `total_cost_usd` | `float \| null` | Total cost in USD (at provider rates) |
| `avg_latency_ms` | `float \| null` | Average request latency in milliseconds |

### Important Constraints

1. **All fields are optional (nullable)**. The report must accept and serialize `null` values for any of these fields.

2. **Tokens and cost are scenario metadata, not measured spend**. These figures are:
   - Based on provider pricing information
   - Estimates from token-counting logic
   - Not validated against actual billing data
   - Intended for cost modeling and scenario planning, not accounting

3. **Unknown values are represented as JSON `null`**. When token counting or cost estimation is not available, the field is `null`, not `0` or omitted.

## Byte Stability

The report includes an `input_sha256` hash computed over the canonical JSON representation of all inputs (provider, execution, metrics, generated_at) with:
- Sorted dictionary keys at all nesting levels
- Compact JSON separators (no whitespace)
- Float rounding to 10 decimal places

This ensures **deterministic output**: identical inputs always produce byte-identical JSON files.

### Generated Timestamp

The `generated_at` field is **caller-provided** for byte-stability:
- When `None` (default), the field is **omitted** from the JSON output
- When provided as `datetime`, it's rendered as ISO 8601 string (e.g., `"2026-08-01T12:34:56.789Z"`)
- When provided as `str`, it's rendered as-is

The `generated_at` value is included in `input_sha256` computation **only when provided**. This means:
- Reports with `generated_at=None` are byte-stable and hash-stable across runs
- Reports with an explicit `generated_at` are byte-stable for identical timestamp values
- Two reports with the same inputs but different `generated_at` values will have different `input_sha256` hashes

## Schema Versioning

The `schema_version` field (currently `"1.0.0"`) allows future evolution of the report structure while maintaining backward compatibility. Changes to field names, types, or semantics require incrementing the schema version.

## Overwrite Protection

By default, `write_report()` rejects overwriting existing files (`overwrite=False`). This prevents accidental loss of previous evaluation results. Explicit opt-in (`overwrite=True`) is required to replace an existing report.

## Empty Set Rejection

The report builder rejects empty evaluation sets (`metrics.n == 0`) and raises `ValueError`. A report must represent at least one evaluated event.
